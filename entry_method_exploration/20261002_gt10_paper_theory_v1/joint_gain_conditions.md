# 从有限搜索工作集合到综合Recall–QPS：条件与非空结构例

2026-10-02，纯手推。本稿补质量与速度应如何共同成立；不进行合成程序、图构建或计时。费用分解是标准记账，结构发现继承[组件命题A/A1](algorithm_and_falsifier.md)，不列为独立创新。这里的非空例是固定图的结构例，不替代[GT1/GT10实际rank正反模型](gt10_theorem_core.md)。

## 1. 完整扩展闭合时，可以比较精确召回

固定query、GTK、K≤L、原主搜索、空visited与合法初始化。比较两个入口集合S_b、S_c，各自有阈值τ_b、τ_c，使对应高分可达组件C_b、C_c恰好都为L。保留A的统一有限分数/自然pool合同和GTK对全部非GTK的严格native优先；或使用A3中safe=potential且容量为L的强条件。

A1给完整扩展集合恰为对应C，最终pool也恰为C。因此

`R_K(S_r)=|GTK∩C_r|/K`，`N_r=|S_r∪N⁺(C_r)|`，`E_r=Σ_(v∈C_r) actual_row_slots(v)`。

第一式是精确质量，不只是下界：最终pool=C，GTK∩C成员在C中严格优于非GTK，总数≤K，所以输出前K恰含全部这些成员。没有在别的组件继续探索的漏项，因为capacity等于L已经关闭所有低分扩展。评分ID和物理槽数仍含初始低分、拒收邻居、padding/重复扫描。

若两组件大小小于L，这份精确终局与完整工作量比较不成立；不能沿用前缀数替代它。

## 2. 什么时候还能支付全部线上费用

对一份固定事前工作负载，串行完整查询时间写为

`T_r = C_route,r + c_d N_r + c_s E_r + Z_r`。

`C_route`包括全部query准备、路由和seed处理，N/E定义如上；`Z`包括pool插入、rewind、visited/批次管理、预取与cache效应、结果处理及所有其他未计项。若硬件上的距离路径/slot成本不一致，也在Z里完整保留，或者改用逐路径成本合同。c_d/c_s不是由NDC统计自动获得的固定硬件常数，不能擅自假定真实wall与计数成正比。

此式作为记账恒等式本身没有预测力。只有独立可信的服务/费用前件，例如候选相对baseline的route与Z总增量有上界B，才给可用充分条件：

`E[c_d(N_b−N_c)+c_s(E_b−E_c)] > B`

且

`E[(C_route,c−C_route,b)+(Z_c−Z_b)] ≤ B`，

便有`E[T_c]<E[T_b]`。同时若`E[|GTK∩C_c|]≥E[|GTK∩C_b|]`，质量不降；若质量严格提高则二者共同提高。QPS使用完整wall的`1/E[T]`，不使用`E[1/T]`，也不拼接独立分项计时。

费用前件未确认时，不能由更少评分宣布QPS增益。这份条件明确“GT10应找到覆盖更好、邻接首次评分较少、且新增线上成本可支付的组件”，不是训练样本更充分便自动成功。

## 3. 结构条件不是空集

手工取L≥103。图含两个各L节点的高分有向cycle C_g、C_b，以及一个共享低分节点z和L个私有低分节点x_v。C_g每行两槽为cycle下一节点和同一个z；C_b每行两槽为cycle下一节点和各自的x_v。z指C_b入口，x_v指C_g入口；必要的第二槽重复合法边。整图强连通。

取raw-IP query q=(1,0)。C_g中选100个节点第一坐标为严格不同的`2+j/256`（j=1,…,100），其余第一坐标1.5；C_b为1，全部低分节点第一坐标0；第二坐标选不同有限值以区分向量。于是官方GT1/GT100全在C_g，并与全部非GTK严格分离。τ=.5使两个高分诱导可达组件分别为C_g、C_b，每个恰L。good初始化从C_g余下至少三个非GTK节点选择，bad初始化任意三个C_b节点；两边均没有初始化GTK。

两个入口动作的Recall@1/@100为1与0。首次评分数为

`N_g=L+1`、`N_b=2L`，而物理槽数两边均为`E=2L`。

原因是cycle发现其所有高分节点；good的外邻居只有共用z，bad每行有不同私有x_v。所有低分点在完整高分前缀结束前尚未扩展，并在高分占满L后被淘汰。因此首次评分节省L−1次，而不是假称两边扫描槽数也减少。

若在事前声明的真实费用合同内，路由与其他残余增量小于`c_d(L−1)`，该例同时改善质量和完整时间。没有该合同，它只证明结构质量与评分数可以共同改善。本文没有任何计时数据；此合法图/入口例不证明当前NSG构图器或GT10画像会选择这些入口。

## 4. 在论文中的正确地位

这是把搜索发现与完整成本条件连起来的适配分析：rank画像理论负责候选入口如何变化，图条件负责实际质量/完整工作集合，收费条件负责QPS。三层缺一不可。GT1/GT10正反模型给了真实rank可实现性，但没有硬件QPS；本结构例给了共同质量/工作节省的非空条件，但没有GT10入口生成保证。不能把两例拼成已经证明的同一个端到端GT10共同收益模型。

真实模型/共享默认/complete wall仍须独立验证。该补充允许离线投入增加，也保留“综合QPS–Recall要提高”的核心要求。
