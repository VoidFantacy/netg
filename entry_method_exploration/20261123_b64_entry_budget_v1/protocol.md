# E230 WebVid 按入口分配 B64 尾部预算

在 WebVid soft-t1 的同一 E229 SPAN4、底库、原图及三路 GT10 路由上比较原版 B32、旧 B64 全精算和新版 B64。三法均沿原表前三路合并顺序，去重并排除主搜索原返回，剩余 ID 以原 raw-IP 完整精算，按原严格 Top-K 合并。冻结 E226 原版 B32 和 B64，统一保留每行的原 B32 有序前缀。

新版 K1 将每路截到最多 56，三路均匀。新版 K100 按路由已经产生的画像距离，给两路最近的入口各 64 个，剩下一路 40 个。相同画像距离时取原路由次序最后者为最远。画像距离只决定幅度，实际合并仍按原路由次序。K100 另做均匀 56/56/56 的同原始名额控制，完整计时，实际去重后精算数逐点量，表中呈现。两幅图按用户要求只有 B32、旧 B64、新 B64 三条曲线。

从 WebVid 公开查询物理行 0 起依次取前 3,072 条，只保留与 E229 的诊断窗、E183/E226 的 20,000 条画像拟合原向量和本轮已选行精确向量字节互斥的记录。该确认窗历史上用于旧方法。先冻结安全角色、配置、代码和策略，再计时。真实 K1 和 K100 各自搜索；按物理行绑定同一官方 GT100，K1 取首名。所有计时结束前不读取公开真值成员。

K1 网格 L104/128/144/160/176/184/192/200/216/224/256。K100 网格 L156/160/168/176/180/184/188/192/196/200/204/208/212/216/220/224/232/244。K1 三臂与 K100 四臂共 105 点、210 个 CPU15 单线程完整批次。每点两遍，旋转首臂与反向重复。完整 wall 包含路由、主搜索、配额决策、去重、精算、合并与正常批对象共同开销。加载、预热、写盘、资格验证及 GT 评分在 wall 外。前 256 条做同池包含与独立标量 Top-K 全排序。另对 E226 旧公共窗重叠物理行核旧方法返回。

K1 预设目标 79/80/81/82/83/84/85/86/87%，K100 目标 71/72/73/74/74.5/75/75.5/76/76.5/77%。同一目标比较各方法最快实测点的完整 QPS 和慢遍对快遍。K100 主诊断 L208 和 75.5% 目标。逐档比较相对 B32 和旧 B64 的救回、损伤与候选实际精算量，同预算比较新版与均匀 56。计时重复范围为描述性证据，折线仅在召回实测重叠范围内描述。
