# E217 复用 GT10 入口取补点候选

COCO、WebVid 的真 K1/K100 共 15,906 个训练角色 dev/cal 状态。BKT4/BKT8 分别每个入口挂最多 4/8 个代表，在线只按全维余弦从原三个入口的候选中取一个，读 E216 的预编漏点表。B32-fit 同 L 的实际精算数在所有回放查询上逐条一致，B32-fit、CACHE 的 ID、距离、入口和画像分数与 E216 的八组回放包逐字节一致。首轮四个场景均无合格臂，正式测试点为 0。

## 实际回放与桶内选择上限

单位为相对同查询 B32-fit L184 的净正确成员数，栏内为 dev / cal。上限实际重算桶内每个代表的固定替换动作，允许回退 B32，再用 GT 选择其中命中最多的动作。此项沿用相同尾部替换顺序和精算数。

| 数据集 / K | B32-fit L192 所需净增 | CACHE | BKT4 实际 | BKT8 实际 | BKT8 桶内上限 |
| --- | ---: | ---: | ---: | ---: | ---: |
| COCO / 1 | +2 / +2 | +1 / +3 | 0 / 0 | +1 / +1 | +5 / +3 |
| COCO / 100 | +444 / +412 | +421 / +376 | +179 / +137 | +224 / +199 | +1,024 / +994 |
| WebVid / 1 | +2 / +7 | +11 / +19 | −1 / +5 | 0 / +6 | +28 / +21 |
| WebVid / 100 | +1,119 / +1,349 | +787 / +939 | +80 / +146 | +185 / +254 | +1,171 / +1,220 |

COCO K100 两窗的代表动作已有足够空间。以校准窗为例，按全维余弦实际净救回 199 个，低于 CACHE 的 376；桶内按最终 Top-K 命中选代表、允许回退时净增上限为 994，高于 L192 所需的 412。WebVid K1 BKT8 校准窗的对应数字为 6、19、21 和 7。WebVid K100 校准窗的上限仍比参考少 129 个，现有短名单的单代表动作空间需要补充。二次回放逐查询核对实际按相似度选出的 ID 与距离，全部复现原 BKT 返回。

## 补点重放费用

CPU15 单线程，每臂两遍。下表为相对同期 B32-fit 的额外微秒/查询，使用冻结主返回。模型文件大小为单份 BKT8 桶目录、代表向量及其预编表的合计，BKT4 同台加载这份模型。构建额外用时约 0.2 s/集，复用 E216 已有的预编表和单位向量。

| 数据集 / K | CACHE 增量 | BKT4 增量 | BKT8 增量 | BKT8 相对 CACHE 节省 |
| --- | ---: | ---: | ---: | ---: |
| COCO / 1 | 14.78 | 3.01 | 4.48 | 10.30 |
| COCO / 100 | 16.29 | 4.12 | 5.78 | 10.51 |
| WebVid / 1 | 16.15 | 3.33 | 4.56 | 11.59 |
| WebVid / 100 | 17.97 | 4.97 | 5.98 | 11.99 |

COCO 3,593 个唯一代表，模型 7.85 MiB。WebVid 3,923 个唯一代表，模型 9.16 MiB。这里的时间只覆盖补点重放，端到端 QPS 尚未测量。两窗沿用已曝光的训练角色。本轮结论适用于当前代表容量、余弦选择以及每次最多用一个预编表的动作空间。
