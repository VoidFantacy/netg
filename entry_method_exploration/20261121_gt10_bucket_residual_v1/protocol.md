# E217 复用 GT10 入口取补点候选

问题是入口分桶能否保住 E216 相近查询补点的质量，同时省去候选查找的小 HNSW。使用 COCO hard、WebVid soft-t1、原 GT10、E211 SPAN4 和 E216 fit-only B32/CACHE。训练、回放和正式测试各自使用固定窗口。

## 候选构造

按 E206 K100/L184 实际选出的三个入口，把 fit 查询放入对应入口桶。每桶取离均值方向最近的一个真实 fit 查询，再按全维余弦做贪心最远点选取，最多 8 个，保留可重复的顺序。BKT4 与 BKT8 分别使用各行前 4/8 个代表。在线复用 GT10 三个入口，合并去重后最多算 12/24 个查询代表的全维点积，取最相近代表（同分取较小 fit 序号），读 E216 的预编遗漏表。沿 E216 保留 B32 行前 16 个、最多替换 16 个尾部位置、排除已在原三行和主返回的 ID、逐查询保持真实精算数，用原始 raw-IP 及严格 Top-K 合并。模型部署只需桶、代表向量和其 CACHE 行。空桶或不足配额回到相应 B32 候选。

## 离线回放

按 E206/E216 的同一 identity 分组 dev/cal 回放全部已有真 K1/K100 L184 主返回。对照 E216 同查 B32-fit 和 CACHE 的实际返回、B32-fit L192 参考。离线额外报告桶内全部代表预编表提供的、原主返回与 B32 精算池之外的正确成员数，及任何同预算选择的乐观净命中上限。实际合并另计救回、损伤、净增、实际候选数及补点重放时间。起始 128 条做逐条精算与独立标量全排序核验。没有测试 GT 参与。

按数据集/K 资格判定。候选须 dev、cal 均相对同 L B32-fit 正净增，且在两窗均至少达到 B32-fit L192，或在两窗均至少达到原 CACHE 同 L。两桶同时合格时优先 BKT4。开放保留所有诊断数据，资格只用来选本轮完整计时重点。

## 正式计时与判定

每个合格场景在公共查询第 3072–6143 行（零基）同期比较 GT10、完整 B32、B32-fit、原 CACHE 与合格桶。在 L176/184/192/200/208/216/224/232/240/248/256，每点两遍完整 CPU15/T1 wall，顺序轮换且次遍反向，预热 256。GT 在所有计时完成后评估。这一窗和 E216 的首 3072 条不重叠，保留其他历史曝光边界。按各桶点的实际召回，以所有 L 中达到该召回的最快实测控制作为参照。保留各自两遍、同 L 对照、完整曲线、模型字节和离线成本。若在至少两个相邻实测预算档均有超过最快达标控制且慢遍仍快于对应控制快遍的收益，再依结果决定四集扩测；两个独立场景的质量和费用分别报告。
