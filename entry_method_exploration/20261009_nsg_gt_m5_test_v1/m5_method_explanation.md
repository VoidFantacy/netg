# M5 方法说明：基于 GT10 的残差目标补全

**M5 正在研究。** 两数据集五档 L 的完整复测已经完成，见[实测报告](analysis_v2/report.md)与[曲线](figures_v2/recall_qps_nsg_gt_m5.png)。

**M5 确实基于 GT10：它完整保留 GT10 的入口路由和原 NSG 主搜索，再加一层输出补全。** GT10 的画像表示“哪些查询适合从这个真实 hub 开始搜索”。新查询先取得原 Micro-HNSW 小图实际返回的三个画像，取它们绑定的真实 hub ID 作为 NSG 入口；并非额外精确扫描所有画像。M5 按原返回顺序复用这三个真实标签，同时用它们寻址一张小表。

| 方法 | 入口 | 主搜索之后 |
|---|---|---|
| NSG 基线 | 原图固定入口 | 直接返回 |
| GT10 | 原画像路由的三个真实入口 | 直接返回 |
| M5 | 与 GT10 完全相同 | 查表、补充评分、合并返回 |

这次 Web 使用 GT10-soft-t1，Yandex 使用 GT10-hard。三方法共用原底图、raw-IP 度量和 scalar 搜索核；M5 不改画像、入口顺序、visited、展开或停止规则。表中的目标只参与最终输出，既不是新入口，也不触发第二次图搜索。[实际调用链](src/benchmark_v2.cpp)

离线构表时，先对每个 TRAIN 查询取得真实的 GT10 三入口和原搜索返回，再找出“真值里有、返回里没有”的目标。实际冻结表用每集 20K 训练查询；遗漏监督来自 Web 的 K1/L800、K100/L1000，以及 Yandex 的 K1/L100、K100/L200。M5 学的是这些实际遗漏，而不是简单存每个画像附近的点。

构表器给每个“标签—目标 ID”组合计算新增覆盖收益：新覆盖一条遗漏 GT1 记 100 分，新覆盖一条遗漏 GT100 记 1 分。这个比例使两项 Recall 的平均贡献等权。随后全局贪心选当前收益最大的组合，每个标签最多保留 8 个目标。某查询的某目标已被它的一个标签覆盖后，另外两个标签再存同一目标，不会重复获得该查询的收益；并列按标签槽位、目标 ID 决定。每集最终只有一张 K1/K100 共用表，行内顺序由选入顺序固定。[实际构表器](frozen_m5_source/compile_postings.py)

在线执行可以写成：

```text
查询 → 原 GT10 路由三个标签 → 原 NSG 搜索得到 R
                       ↓
                  读取三行小表
                       ↓
             去重、排除 R 中已有 ID 得到 C
                       ↓
           对 R 和 C 用原 scalar raw-IP 重新评分
                       ↓
                 严格比较，合并为 TopK
```

三行各最多 8 个 ID，因此读取最多 24 个目标，去重后通常更少；没有新增候选就保留原结果。有候选时，程序不仅评分新目标，也重评原返回 R：K1 最多 25 次额外评分，K100 最多 124 次。只有新目标严格优于当前最差项才替换；相等时保留先前项，最终输出按实际评分排序。它不读取测试查询的真值。[查表与合并代码](src/runtime.hpp)

M5 希望用少量直接访问补回图搜索没走到的好目标。例如 GT1 不在 R，但出现在某行表中，补充评分便有机会把它送进返回。真正的难点是迁移：训练时这个标签常漏的目标，是否也是新查询会漏的目标？若实际遗漏不在所读三行，M5 无法补回。

**同 L 的 M5 用来观察补全本身的作用。** 主搜索工作相同，额外查表、访存、重评分和合并通常要付时间，不能预设 QPS 提高。此前低 L 主候选则尝试少搜索，再靠补全追回质量；成功需要省下的搜索时间大于全部补全成本，同时补回足够多的遗漏。这次五档 L 都用原冻结表，不按测试结果换目标或调表，直接比较每一档 NSG、GT 和 M5 的实际 Recall 与完整 QPS。

表文件约 52 KiB，保存 ID 和映射，不复制目标向量；小表并不等于免费，完整成本还包括目标向量的随机访问、原返回重评分和合并。评分与真值排序不一致、近并列或分布变化也会影响收益，不能无条件声称同 L 的真实 Recall 只升不降。

2026-10-06 的历史结果只有 Web Recall@1 的局部信号；低 L 主候选约提速 24%，旧质量门未通过，其他三个点损失 Recall。这些旧结果不替代本次公开测试。[历史报告](../../research_snapshots/20261006_results/report.md)；完整算法及条件见[方法稿](advisor_report/concise_v1/method_report.md)。本轮同 L 的20点均提高 Recall、真值近邻成员损伤0，但配对QPS中位均下降约0.16%–4.85%。WebVid Recall@1有两组离散跨L综合优势；Yandex增益很小，当前默认仍保留GT10，M5继续标为正在研究。
