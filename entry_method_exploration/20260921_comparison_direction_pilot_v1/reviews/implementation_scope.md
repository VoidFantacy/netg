# 执行前的实现细节与审计范围

此说明在全量标签生成中、模型训练和接受载荷物化前写入。它不根据模型表现改变方法或控制。

- 置换控制在每个CV训练折内部打乱整条响应行，验证折仍用真实响应评分；最终模型在全fit内部置换。这样避免把验证query的标签通过全局置换送进训练折。seed固定，全部H和四种响应同一行共同置换。
- GraphRecall的CV选择使用召回效用（时间系数0）；其余学习臂使用原0.1成本权重。每臂两K等权选择同一个alpha，K头分别导出。
- 接受集未计划生成全H穷举标签。全H oracle/决策regret可由fit完整标签计算；接受集仅能提供属于H单入口/原GT10动作域的已实测策略的召回oracle及相应regret，明确标为“已测动作下界”，不能冒称全H oracle。固定NSG入口未必属于H，因此从此oracle排除，仍完整保留为性能控制。接受无逐query独立时间标签，不构造虚假的逐query时间regret。
- 增加冻结模型在fit上的原生返回回放：全部11方法、K1/K100/L128、一次warm/plain/count，主要检查所选动作的返回hash/命中/原GT10恢复。该批为训练正确性审计，不纳入正式QPS主表。新增约54万NSG调用，全部预计调用仍低于原6000万预算。
- 正式接受不以小规模统计、方向覆盖、训练均值或CV正负决定是否执行。按照原协议完成11方法L128和六方法五预算曲线。
- 原生源码、二进制、库、原协议及参数锁在第一次真实作业前冻结；后续Python分析/验收代码分别记录源码冻结。新脚本可在标签作业期间编写，但训练/数值计算/正式评测串行等待标签进程退出。
- 两阶段共用原12小时保护上限；第二阶段计时起点继承第一阶段开始时间。第一阶段已加载的控制器源保留为`execute.stage1_initial.py`，后续控制器只将此全程时间保护显式跨阶段继承；没有改变原生搜索或标签计时。原GT10小图/画像/ID及原搜索源码另与既有E117身份比对通过，记录于`preserved_assets.json`。
