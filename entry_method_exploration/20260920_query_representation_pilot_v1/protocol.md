# E104 查询侧表示 pilot 执行协议

2026-09-20 用户明确“验证吧”，执行[研究阶段协议](../20260920_query_representation_research_v1/protocol.md)。原文逐字保存为 protocol.research_original.md；模型、超参数、收益门、表示门、完整 wall 门和停止规则均继承，不按新结果改变。

执行前澄清：

1. 余量门只用 fit 前2048行。cal 的512行仅在本版模型全部冻结后打开 query/GT、生成一次候选标签并评估；准备阶段只检查其 config/row ID 元数据。旧开发池身份不变。
2. 两集每条 query 取当前默认小图 top3、另一个固定GT10 top3的并集，按原 anchor 的 hnswlib IP 精确评分补足8个，距离 ties 按真实 hub ID。最终8候选按真实ID升序，56集合的输入也升序，与原 GT10 的实际入口顺序匹配。候选不看 GT。
3. 每集 fit 预锁位置0,128,…,1920：当前 anchor 三入口的六种排列分别在真实 K1/K100、L128 下执行；比较完整返回ID/距离bits和NDC。另与链接的原 search_new 路径比较相同入口。顺序改变结果则按原协议停止，不训练。
4. 原 anchor 用 raw query 路由；网络输入单位查询。额外记录 raw/单位查询路由差异，不把有限精度的差异归因于学习。底图始终用 raw query。
5. 标签阶段单线程 CPU15，数值库1线程，独立串行运行，不产正式QPS。大图只读加载，记录大小/mtime并继承既有内容身份，不能宣称重新hash完整底库。小模型、源码和新输入使用SHA。只复制本次 fit 子集，旧输入/模型/图不写入。
6. 资源门：/data 至少4GiB空闲，搜索RSS≤40GiB，训练RSS≤8GiB；训练最多30分钟，准备/标签/训练总计2小时，完整wall另限4小时；主搜索上限110万。新版本建立时起计，启动前估计剩余成本。失败/中断保留产物，不自动重复或择优计时。

所有新源码、binary、配置在首次搜索前封存；修复须保留旧版及修订记录，方法选择与数据角色不得作为“修复”改动。最终交付实际调用数、全部进入的门及未进入原因、配对结果、完整wall（若门通过）和保护核验。
