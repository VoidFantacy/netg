# E218 入口桶净收益选择与双表动作

## 单表选择

用三个身份隔离的 fit 折重建 B32、BKT8 代表、预编漏点和候选摘要。对各折留出查询的桶内代表做真实 raw-IP 精算与 Top-K 合并，共 24,047 个训练状态、509,823 个动作标签。COCO K100 和 WebVid K1 的全 fit 原 E217 短名单共回放 7,953 个 dev/cal 状态。所有动作保持相应基准逐查询的实际精算数。全 fit 余弦代表与 B32-fit 的回放 ID 和距离逐条复现 E217。原生运行和独立计数对齐。

ROUTE 输入余弦和入口重合，RETURN 加主返回前八位（K1 只用首位）重合，SUMMARY 再加真实候选原向量均值的 16D 摘要与当前第 K 名的分差。三版共享相同的逐动作净命中标签，预测收益不大于零时保留 B32。下表为相对同窗 B32-fit L184 的净增，格式为 dev / cal。

| 场景 | B32-fit L192 所需 | CACHE | BKT8 余弦 | ROUTE | RETURN | SUMMARY |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| COCO K100 | +444 / +412 | +421 / +376 | +224 / +199 | +206 / +204 | +224 / +201 | +229 / +206 |
| WebVid K1 | +2 / +7 | +11 / +19 | 0 / +6 | 0 / +2 | 0 / +2 | +2 / +3 |

COCO K100 校准窗，SUMMARY 把救回从 400 增至 414，同时误删从 201 增至 208，净收益只多 7 个，离 L192 仍差 206。原生补点重放里，BKT8 与 SUMMARY 分别为 18.70、21.97 微秒/查询，相差 3.27 微秒。WebVid K1 SUMMARY 校准窗净增 3，旧余弦为 6，原 CACHE 为 19。COCO 和 WebVid 的 K 专用选择器均未达到两窗条件，正式测量点为 0。补点重放使用冻结主返回、CPU15 单线程、每臂两遍，完整主图搜索未计入这些数字。

## WebVid K100 双表动作上限

在保持 B32 逐查询精算数的条件下，对 3,999 个 dev/cal 状态枚举 949,006 个代表对。两表各最多取 8 个新 ID，跨表去重并排除原主返回和 B32 已有候选，再按原精算与 Top-K 合并。上限允许单表、双表或保留 B32。单表上限与 E217 完全一致，另采样 64 个动作核对原生四路与记忆化精算输出逐位一致。

| WebVid K100 | 追平 L192 所需 | 单表上限 | 含双表上限 | 含双表上限相对 L192 |
| --- | ---: | ---: | ---: | ---: |
| dev | +1,119 | +1,171 | +1,357 | +238 |
| cal | +1,349 | +1,220 | +1,408 | +59 |

双表扩大了可选动作范围，校准窗的事后余量为 59 个正确成员。结果来自训练窗 GT 事后选择。当前选择器的效果与这部分余量有较大距离，可优先用同一动作空间验证更有区分力的、能够指向漏点 ID 的选择信号和回退，届时再判断双表在线是否合算。
