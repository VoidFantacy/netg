# 拟合前语义修正：GT1包含代理不等于所有同分ID下的Recall@1

原fit.py在读取标签检查时停止，尚未调用任何真实数据聚合或拟合，未生成外折动作/门结果。源代码、fit_frozen.json、合成通过记录与失败log保留。此次是原前件假设错误被审计揭示，不将其说成数组读取错误。

完整扫描发现Web位置282、source行12330上107个动作（含默认）存在bit0=1而真实K1命中0；其余Web query及Y所有动作一致。两ID345234/344262的base向量逐字相同，float64内积也相同；GT1列与搜索tie顺序选择了不同ID。所有位图popcount与实际K100一致，100位之外无额外bit。此为记录106/E111已发现的同一base重复向量边界，在当前query批次的另一个实例。

原协议要求逐动作bit0完全等于真实K1的前件因此不成立。更新的前件是：TargetService拟合**原K100池中逐GT成员包含**，对K1使用GT1区域作为包含概率代理；它不是严格的K1充分统计。表、温度、区域、角色、门、成本和所有超参数不变，不替换任何GT/命中、不删除该query，也不篡改K1评估。GT1Group、GlobalCost和所有实际外折收益仍使用真实hits1.u8/真实hits100.u8。

这项修正不影响K100服务标签定义；K1增加一个同分ID桥接误差。当前批次一个query的直接均值影响上限为1/4096=0.024414pp，但不能据此声称训练参数影响也仅限这个query。完整配对收益与门仍由真实K1判定，不用代理质量补过。

因为尚未产生任何拟合结果，允许按明确修正前件继续原服务假设的首次拟合；使用fit_v2.py、models_v2、results_v2、fit_frozen_v2和fit_v2.log保留前后身份。原失败件不覆盖，不改变已停止E121/E122/E111。v2另锁此文、完整位图差异审计及重复向量身份文件。
