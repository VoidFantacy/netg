# E98 WebVid GT10 / NSG 与完整 HNSW 搜索成本诊断

用户授权分析距离次数优势为何未转化为速度，以及实现中是否有未优化项。只定位现有实现成本，不训练模型、不改图、不部署新默认。E97正式结果和封存、主源码和静态库只读。

固定WebVid同一完整2.505M/512d原IP底库与公开10K query，原GT10-soft画像/815真实hub、同一序列化Micro-HNSW和完整HNSW拓扑。该公开测试已有曝光，本次是实现诊断，不是新方法泛化验证；不按失败query挑样。只K100，另K1/L1250作返回K成本控制。基础分项覆盖L100/400/1250；同预算只用于成本解释，性能结论保留原Recall-QPS证据。

CPU15，进程/OMP/BLAS/MKL均1，串行，无并行训练/评测。所有加载、哈希、GT评分、文件输出不计在线wall。原生plain一轮warmup+三轮计时；分项时间和SIGPROF采样独立于plain，不将采样/插桩时间作正式QPS。基础输出需对齐E97的IDs、距离bits、入口。

没有perf工具且内核perf_event_paranoid=4；采用不修改系统设置的1ms ITIMER_PROF指令地址采样，区分距离函数、候选池/遍历、libc等CPU占比。样本同时覆盖访存等待，不能解读为硬件cache-miss计数。分项计时包含route/graph/输出记账，总wall单独测。

根据源码预先指定三个局部反事实：仅NSG增加邻居lookahead1的visited/向量首缓存线预取；仅插入候选时未满pool不搬动无效尾部；两者结合。只在K100/L1250各做warmup+3次plain，完整10K query核验ID/距离bits/入口不变，不能在数值不同后仍称语义等价。若编译或parity失败保留记录修复，不扩成参数网格。距离内核用相同固定地址流做有限microbenchmark，注明cache/算术身份，不能据微基准替代完整搜索速度。

搜索调用硬上限600000，进程RSS<64GiB，新盘<1GiB，单个子进程不超过1800秒。最终交付分项成本、采样热点、反事实原始轮次/一致性、明确优化优先级与尚未量化项，并同步summary/spec/s-target/s-experiment及新历史卡。

2026-09-16基础阶段完成后的计量修订（在检查三个优化控制的计时结果之前）：原始双方法进程同时恢复NSG与完整HNSW，而三个变体只加载NSG，存活内存不同。为避免把这一差异当成优化收益，追加同一original二进制的`original_only`模式（命令第四参数），仅加载NSG，K100/L1250，完整10K、warmup+3轮，无源码变化。优化收益优先相对该匹配加载方式的基线报告；原双方法基线仍保留用于剖析HNSW差距。总搜索上限仍600000，计划实际520000；不是追加方法/预算网格。

补充一致性验收：三个实现控制在plain计时完成后各独立运行一次完整10K count分支，核对逐query route/graph NDC也与E97一致，并再次核验ID、距离bits与入口。计数器运行不作为QPS；编译仅在所有主要plain控制退出后进行。加上匹配内存基线共计划550000次search，仍不超过600000。这样避免把候选等距处理造成的搜索工作量变化误算为实现优化。
