# E116之后：只改入口选择，下一步到底应改什么

2026-09-20。`COMPLETE_READONLY_THEORY_REVIEW`。完整复读用户指定的[19:00理论报告](../20260920_until1900_theory_v1/report.md)，核对E116源码、冻结模型和缓存，并沿历史卡片回读原协议。此次只做理论与已有结果分析，0新ANN/NSG、训练、GT、图、编译或QPS；没有生成新选择器，没有打开未曝光held-out。当前Web GT10-soft-t1、Yandex GT10-hard与生产E99保持。

**结论：不继续扩大E116的候选、绑定数或筛选阈值。更值得研究的是跨查询共享的入口集合决策：从当前三个候选中选其中一个真实入口，或保留原三入口，同时预测真实召回变化和时间变化。** 这是需要先证伪的研究候选，不是已证明有效的新方法。“共享特征”“小评分器”“真实reward”本身都已有实验；本版具体差异是同一次实际路由下的可变入口数量、四种动作语义，以及相对最强固定动作的净收益要求。旧实验仍留下预测信息不足的实质风险。

全过程保持底图、距离、L、候选池、展开和停止规则不变。只在主搜索前决定传入的真实ID集合。E110强制首展开和此前搜索成本提案不属于本次推荐。

## 1. E116具体告诉了我们什么

### 1.1 搜索调用很多，单个决策的有效信息仍很少

E116每集10000条选择query，共5064/6192个候选绑定。此次从所有冻结标签重算，没有删去零差或失败样本：

| 统计 | WebVid | Yandex |
|---|---:|---:|
| 每候选支持query数中位数 | 37 | 34 |
| 每候选K1非零响应数中位数 | 0 | 0 |
| 完全没有K1变化的候选 | 2867/5064 | 4454/6192 |
| Cost所选16编辑的支持中位数 | 45.5 | 40.5 |
| 所选编辑完全没有K1变化 | 8/16 | 8/16 |
| 所选编辑K100非零响应中位数 | 8 | 5.5 |

因此“1.71百万次NSG”不是1.71百万独立训练query；同query的动作和计时重跑尤其不能增加独立query数。零响应也是合法观测，但不能把“没有看到K1损伤”写成“已经学到K1安全”。[全部统计](results/summary.json) · [所有选中编辑](results/selected_edit_details.json)

E116按源行奇偶把选择数据分成两半，**两半都参与挑选**，所以“两半都正”是一个筛选规则，并非独立验证。后续4096条审计query不参与本版绑定选择，这点保持；但它们在项目历史中已曝光，不能改称全项目盲测。支持稀疏与筛选偏差是明确风险，不能仅凭本分析判定它们解释了全部失败。

### 1.2 组合干扰不能包办失败解释

按审计query实际命中多少个被替换槽位，把全部输出分为0/1/2/3编辑；以下是Cost的完整非零编辑合并结果。K100列为净GT成员命中数，不是query个数，也不是pp。

| 数据 | 仅1个绑定改变：query数 / K1净命中 / K100净命中 | 至少2个改变：query数 / K1 / K100 |
|---|---|---|
| Web | 240 / −2 / +3 | 19 / −1 / +1 |
| Yandex | 299 / +2 / −40 | 10 / −1 / +10 |

Yandex的K100损失已出现在只有一个绑定改变的query；多个改变的query反而补回10个命中。Web的K1损失也已出现在单改变组。不能据此继续讲“单个编辑好，只是组合坏”，然后重启组合调参。多改变query缺少逐个编辑的审计反事实，故本表也不是精确交互项的估计。[含RecallControl的完整分解](results/audit_overlap.json)

### 1.3 已经学习了时间，但标签不够稳

E116 Cost确实使用了真实搜索时间差，问题不是它完全忽略QPS。每个query的所有动作连续执行两遍，第二遍逆序；筛选用两次时间的平均值。对所选16编辑×2半共32个均值：

| 检查 | Web | Yandex |
|---|---:|---:|
| 第1次重复时间差≤0的半组 | 29/32 | 30/32 |
| 第2次重复时间差≤0的半组 | 12/32 | 10/32 |
| 两次重复符号相反的半组 | 23/32 | 24/32 |
| 两半×两次重复全部非正的编辑 | 0/16 | 1/16 |

这是已保存计时的符号不稳定性，不是新QPS。连续执行同query的多个相近动作与线上每query只执行一次的缓存环境不同；上述差异与这种影响相容，但现有结果未独立隔离缓存、顺序和噪声各自的因果份额。不能直接将第一遍认定无效，或事后改用第二遍重选模型。[训练循环](../20260920_entry_id_pilot_v1/src/experiment.cpp) · [复算与一致性检查](reviews/numeric_verification.json)

原完整wall仍是最终证据：Cost的Web K1/K100 ΔQPS为+0.179/−0.789%，Yandex为+0.422/−0.305%；召回四区间全跨0，原停止结论不变。[原报告](../20260920_entry_id_pilot_v1/report.md)

### 1.4 局部均值排序也不等于总体收益排序

单编辑的全量召回增量严格等于 `P(槽位被路由到) × E[完整入口替换的召回差 | 该槽位]`。E116按两半中的较小条件均值排序，没有乘槽位覆盖率，因此排序与全量目标有偏离。多个编辑还存在重叠，不能直接把这些全量单编辑增量相加当作组合值。这是目标对齐问题；仅修排序并不能补足稀疏信息，也不构成立即重跑E116的理由。

## 2. 理论上应同时优化什么

固定搜索函数 `F(G,q,S,L,K)`。策略π只决定初始集合S；令原策略为π0，定义：

`dR_K(q,π) = R_K(q,S_π(q)) − R_K(q,S_0(q))`，K分别取1、100。

`T_π = T_route + T_features + T_decision + T_original_search + T_output`。

一个对应当前研究目标的总体问题是：最大化 `E[(dR_1+dR_100)/2]`，同时约束 `E[dR_1]≥0`、`E[dR_100]≥0` 和 `E[T_π−T_0]≤0`。是否满足约束必须处理估计误差，不能只看训练均值；等K平均只是排序目标，不能遮盖任何一项下降。

**要学成本，但应预测时间差，而不是每query的QPS。** 单轮相同N下，`QPS=N/T_batch`，提升比例为 `T_0/(T_0+ΔT)−1`（T取每query平均完整时间）。`mean(1/t_q)`不等于批吞吐。入口会改变访问节点、重复计算和访存行为，所以固定主搜索也能改变QPS；NDC只能辅助解释，不能取代时间。一次选择所增加的特征和决策开销必须计入。

成本学习采用与召回同一完整入口动作的配对标签。未来若采集，需要跨query执行块、方法轮换和独立计时重复，保留顺序信息，避免把同query连续多动作计时直接当作线上成本。拟合时间变化与完整wall验收是两个环节；没有一般的低方差逐query时间保证。

## 3. 真正的理论瓶颈：oracle、可见信息、可学习策略是三层

设动作0为原三入口，其差值效用为0。对一个事前固定的标量效用u和线上可见特征φ，有：

`O = E[max_a u(q,a)] ≥ V_φ = E[max_a E[u(q,a)|φ(q)]] ≥ V_Π = sup_{π∈Π} E[u(q,π(φ(q)))]`。

第一处差距是可见信息不足；第二处差距是限制策略表示造成的。有限样本学习还会损失估计精度。这是条件期望与决策函数的基本关系，不是论文新定理；标量u的界也不自动保证两个Recall和时间同时改善。

E116现有训练动作的免费逐query oracle，K1仍可比默认多556/296次命中，K100可多25078/20415次命中。两个K分别取最大值，不保证同一动作同时取得；没有计选择成本。这只能说明所测动作中存在机会，完全没有证明固定槽位能共同使用这些机会。继续扩大oracle不一定增大 `V_φ`。[缓存复算](results/summary.json)

K1配对差D取−1、0、1。令救回概率为g、损伤概率为l，则严格有 `E[D]=g−l`、`Var(D)=g+l−(g−l)^2`。我们要学习的是小的净差g−l，噪声却由救回与损伤的总量决定。更多动作、更多重复计时不能替代更多可迁移的query证据。

以事前固定的M个策略、独立同分布且未参与策略构造的n条query为例，对D∈[−1,1]，经验Bernstein界给出同时下界：

`E[D_π] ≥ mean(D_π) − sqrt(2·s²_π·log(2M/δ)/n) − 14·log(2M/δ)/(3(n−1))`。

它来自将D变换到[0,1]，应用Theorem 4并对M个策略取union bound；s²为无偏样本方差。它表达两个要求：净增益须超过估计不确定性；搜索过的策略越多，不能仍按单次选择计算把握度。E116的原画像/分组已使用历史训练query，动作又经过选择，**不能把此式直接套回旧标签当成泛化证书**。多个K/数据集还需扩充比较族。时间不满足这里的固定有界假设，不能直接沿用。[Maurer与Pontil，COLT 2009](https://www.cs.mcgill.ca/~colt2009/papers/012.pdf)

只把置信门设严会重复E60：所有动作被拒绝、结果不变，并不等于研究进展。改法必须改善信息共享或特征与效用的联系，不能只增加筛选规则。

## 4. 一个范围明确、值得优先证伪的入口方案

### 4.1 四个动作，直接选择真实入口集合

同一次原GT10小图检索得到三个候选，按画像分数排名记为e1、e2、e3（不是按真实ID排序的数组位置）。只定义四个动作：

`A(q) = { {e1,e2,e3}, {e1}, {e2}, {e3} }`。

原三入口是回退动作；允许任何一个候选单独起搜，不强制画像top1作为所有动作的anchor。选定集合后仍按原ID约定传给原搜索，不控制谁先展开，不在搜索中追加入口、重启、剪枝或早停。K、L不随动作改变。这是单入口与原三入口之间的有限选择，暂不增加两入口组合或扩大C8。

每种动作在所有query上有共同语义，例如“使用画像排名第2的入口”，而不是为数千个具体`oldID→newID`分别估计收益。训练仍须记录真实完整动作的R1、R100及时间；四个动作的标签共享query，不能当成4n独立样本，稀疏非零响应也不会凭命名自动消失。

### 4.2 在线信息与实现成本

先限定为已有路由给出的三个画像分数/分数差，以及这三个真实入口对query的raw-IP分数和两种排名的关系。后三个分数最多增加3次base点积，必须计入成本，不能宣称免费复用原搜索计算。现有Router可能只向外返回ID升序结果，若未来实现，需要在不改变路由轨迹的前提下保留真实评分排名；本轮未实现此接口。

理论动机是：画像排名表达query与训练需求的匹配，而实际搜索初始竞争使用真实节点分数。二者排序一致、冲突或接近并列，描述不同的初始化条件；同时观察两者，比只看q或只记hub身份更贴近动作产生作用的位置。**它们不是有限搜索成功的充分统计量**；E15曾使用raw-entry距离、E36曾使用排名/间隔，因此这些特征也不是新发现。

如果需要一个可审查的最小学习器，可固定深度不超过2的共享决策树，叶子保存四动作的`(ΔR1, ΔR100, ΔT)`估计，输出一个动作。树只是约束复杂度和在线代价的载体，不作为创新点；不能失败后逐轮加深、加候选和扫阈值。成本约束、缺少支持时的回退及动作决策规则须在新协议中先固定，尚未选择树或训练任何参数。

### 4.3 为什么它有依据，为什么又不能承诺有效

E107的相同精确GT10表示下，1→3在18个K/L均值中17负，但仅1个描述性区间排除0；L128的K1救回/损伤为Web58/67、Yandex28/40。即使仅比较画像top1单入口和原三入口，免费逐query二选一相对两者中较强者的K1空间仍分别为`58/4096=1.4160pp`、`28/4096=0.6836pp`。这是由既有增损数得到的恒等式，尚未涉及选择器。

这说明单入口与多入口的真实结果具有互补性，给可变数量提供了事实依据。**该证据来自全H精确路由，不是当前实际ANN top3四动作的标签；不能直接迁用headroom，也没有证明上述特征能识别这些query。** 更少入口也不保证更少总耗时：搜索路径可能更长。E107已有NDC混合变化，必须保持成本学习。[E107原报告](../20260920_until1600_theory_v1/stages/e107_initialization_factorial/report.md)

共享动作的好处只是潜在降低按具体ID划分带来的估计稀疏性；代价是合并了不同hub、图区域，可能引入更大的条件异质性。因此，本方案的实质待证命题是：**存在低成本的初始化关系特征，使四动作的条件净收益能跨query迁移，并超过最好的固定动作及新增决策成本。** 没有这个证据就不应扩大模型。

## 6. 下一步应回答什么，怎样停止

本次优先级是上述四动作候选；全H外重选、多画像/更强网络和搜索干预不作为并行兜底。后续若进入验证，应先用独立版本明确三个问题，不能一开始投入大模型：

1. **机会属于当前可执行动作吗？** 标签必须来自实际ANN给出的同三个候选、原kernel、同K/L。先与原三入口、三个固定单入口规则完整比较；不能拿E107精确路由的数字替代。若最强固定规则已取走全部可用增量，就采用简单解释，不为学习器制造任务。
2. **初始化关系特征能预测净差吗？** 固定小策略在本轮拟合外的接受数据上，须胜过原三入口和训练侧冻结的最强固定动作，报告救回、损伤、K100净成员数及覆盖率；标签置换或常数规则作控制。不能只检查动作分类准确率、fit reward或oracle。未迁移则停止这一特征/动作版本，不追加树深、阈值、seed或候选网格。
3. **新增决策是否值得付费？** 同线程、串行、完整路由/特征/决策/原搜索的wall；K1/K100分别保留，随后只有开发门通过才考虑完整L比较。入口更少不构成QPS证明，单L不构成最终前沿。

这三步是具体的证伪顺序，尚不是已启动的实验协议或队列。训练/接受角色及整个比较族需要先锁定；当前已经反复曝光的4096条不再用于选择规则，也不冒称最终独立测试。若缺少上述信息依据，保留默认并停止这个候选，比连续更换学习器更符合目前证据。
