# 固定主搜索：入口身份选择的理论重审

2026-09-20。`THEORY_ONLY_CONDITIONAL_CANDIDATE_UNRUN`。用户纠正研究范围后，只讨论在主搜索开始前选择真实入口。原NSG、距离、候选池L、展开与停止规则保持原合同。上一轮[搜索成本提案](../20260920_cost_theory_review_v2/report.md)保留原件，但退出当前推荐。

本次0新标签、训练、ANN、NSG、GT、构图、编译或性能评测，未读取原始开发/held-out载荷。默认Web GT10-soft-t1、Yandex GT10-hard与生产E99保持。以下是有条件的研究候选，不是方法通过或实验启动计划。

## 1. 更值得问的问题

现有流程先确定真实入口H，再构造画像和小图，让查询选中H中的三个入口。近期多数后继改变画像、评分或小图；旧E22还改变了槽位到H内入口的映射。换评分器无法直接创造一个H中没有的真实入口。

因此可以研究：**在保留当前GT10查询分组及其路由成本的条件下，是否存在H外的真实节点，能在一组查询的完整三入口搜索中，稳定替代当前某个入口？**

这不是断言H已经成为主要瓶颈。E20的H内oracle仍有空间；E112也实际改过H。这里要改变的是“能被现有查询分组共同利用的动作”，不是仅扩大免费oracle或声称此前从未选择过H。

## 2. 理论关键：最好入口与一组查询能共用的入口不同

设一个固定路由区域B只能输出同一个动作，动作效用为u(q,a)。它能实现的是：

`V(B,C) = max_{a in C} E[u(q,a) | q in B]`。

免费知道每条查询结果的oracle却是：

`O(B,C) = E[max_{a in C} u(q,a) | q in B]`。

总有`V <= O`。提高O不保证提高V；反过来，提高V也不必提高O。考虑同一区域里等概率的两类查询，下表为说明逻辑的Recall@100效用例子，不是NSG实测或真实图构造：

| 查询类型 | 旧动作a | 旧动作b | 新动作c |
|---|---:|---:|---:|
| 第一类 | 1.0 | 0.0 | 0.8 |
| 第二类 | 0.0 | 1.0 | 0.8 |

旧动作的免费oracle已为1.0，区域内最佳固定动作仅0.5。增加c后oracle仍为1.0，区域可实现值却升至0.8。c从未是逐查询最优动作，仍可帮助受限路由器。不能据此断言当前真实数据存在这种c；耗时也尚未进入这个例子。

由此得到一个具体修正：**“必须先证明H内oracle不足，才能研究H外节点”不是普遍必要条件。** 新入口可能降低同一区域内动作效用的冲突，提升可实现收益，而非扩大oracle。旧A+B曾把H外探索放在H内门通过之后；其负结果仍有效，但这个执行顺序不构成数学上的必要性证明。

该不等式与例子只是受限决策的基本事实，不是论文新定理，也不自动克服样本不足。

## 3. 最小具体方法：固定画像和小图，替换它绑定的真实入口

先保持P、序列化Micro-HNSW、标签/同分规则、ef与实际top3槽位输出全部固定。设它返回`r(q)=(s1,s2,s3)`，原绑定为`pi0(s)=h_s`。研究单个编辑：把槽位s的绑定换成同一base里`e not in H`，其余绑定不变。

在线仍是：

`query -> 原GT10小图 -> 三个槽位 -> 绑定表 -> 三个真实ID -> 原NSG`。

不改HNSW内部label，否则同分及轨迹可能变化；用外部绑定表映射真实ID，之后沿用原真实ID升序规则。单次编辑且e在H外保证三个ID仍互异。小图中仍只有原来的H个画像，输出仍是三个真实入口，原图没有新增节点或边。底图本来就含有e。

候选e只能来自训练角色的候选提出过程，例如独立提议折内已有轨迹的节点或训练GT节点；这些只是提议来源，频次、距离、首行覆盖均不充当成功标签。候选先冻结，再在不同查询上判断是否可共用。禁止从已经曝光的最终失败查询挑e，禁止让查询自己的GT直接成为它的“可部署入口”。本轮没有产生任何候选。

该方法先冻结路由分组，让“入口身份是否能改善”成为可分辨的问题。若它无效，不自动转向改P、小图、网络或扩大候选；若以后证明身份变化有效，再另论是否值得共同学习路由。

## 4. 三入口收益与QPS必须一起定义

设`B_s={q:s in r(q)}`。`R_K(q,S)`指从完整三个入口S运行一次原搜索的真实Recall；不是三个单入口Recall之和，也不是独立结果并集。对同一K、L定义：

`dR(q;s,e) = R_K(q,S_{s->e}(q)) - R_K(q,S0(q))`。

固定执行身份下，不属于B_s的查询入口与搜索结果不变，所以总体增量严格为：

`Delta R_K = P(B_s) * E[dR(q;s,e) | B_s]`。

这要求统计B_s中**全部查询的挽救和损伤**。只测原来失败的查询会漏掉被破坏的成功查询。K1、K100分别定义、分别验收；旧K10标签不能改名复用。多个槽位编辑之间会相互作用，不能把单次增量相加当成最终模型表现。

时间目标用完整平均wall。可将变化记成：

`Delta T = P(B_s) * E[dT_search | B_s] + Delta T_other`。

`Delta T_other`包含绑定表、排序、路由、未改变入口查询上的执行时间波动及缓存相互影响等剩余变化；即使小图访问轨迹不变，也不能宣称此项严格为0。这个式子是分账恒等式，不是用分项计时替代完整wall。新增入口可以改变原搜索的访问数和访存局部性，从而改变时间，但没有改搜索算法。

对应吞吐是`QPS=N/T_batch`，同查询数下相对变化为`T0/(T0+Delta T)-1`，其中T0为原完整平均时间。不能训练平均`1/t_q`来冒充批吞吐。目标可以写成“最大化真实Recall，约束完整平均时间不高于默认”；若训练需要代理，必须同时估计召回变化和搜索时间变化，最终仍用完整wall验收。NDC只能是成本特征，不能替代时间标签。`Delta R-lambda*Delta T>0`也不代表二者分别改善。

**一个编辑改善的充分条件很明确：样本外Delta R为正，且完整Delta T不为正。** 条件没有被本轮验证；现有理论不能无条件保证任意冻结NSG都有满足它的H外节点。

## 5. 为什么不能再“每槽挑训练赢家”

E22源码的`remap`已经按到达槽位的查询总命中选动作，不能把“组内平均收益”说成新训练原则。它的fit增长没有迁移，正是本候选最直接的风险。

更换动作空间并不消除统计选择偏差。若20K查询每条选3个槽位，815/821槽位的平均出现支持也仅约74/73条，支持还不均匀；从大量e中挑赢家很容易挑中噪声。不能靠把最低支持阈值写进协议就声称解决了它。

理论候选要成立，至少需要同一编辑在不同训练折的全部受影响查询上保留净收益，而且这种稳定性足以覆盖选择误差及成本。候选提出、选择与最后审计要分离；反复用于接受编辑的折属于训练选择信息。若只能解释几条查询、不同折收益翻转，或没有足够支持估计小增量，应判为信息不足，而不是追加候选、轮数、seed或改成只做Web。

原baseline映射可恢复，只说明动作族包含默认；训练目标不下降也不保证样本外不下降。必须保留整个默认方法作为最终比较，并记录真实救回/新增失败。

## 7. 文献边界与目前判断

[Oguri与Matsui，2024](https://arxiv.org/html/2402.04713v1)在欧氏距离及B-MSNET等条件下分析自适应入口与路径跳数上界。不能把它直接当作本项目raw-IP、有限候选池、三入口真实Recall或wall保证。[GATE原论文§4.1](https://arxiv.org/html/2506.15986v1#S4.SS1)先用平衡聚类选真实hub，再学习入口表示；因此入口ID与路由的关系确实是可以区分的设计对象，但“小入口池、离线学习、轻路由”已有明确前作。

本次最有价值的理论修正是：**寻找可以被现有路由共同利用的入口，不必以提高逐查询oracle为目标。** 最小方法把该问题落实为冻结GT10路由后的真实入口身份编辑，保留三入口联合搜索与完整成本。

它仍缺少两个关键事实：当前GT10分组里是否确有跨查询稳定的H外替代节点；这份净收益是否足以超过估计误差与全部成本。在这两点有证据之前，只保留为有条件候选，不写成“已经找到能提升效果的方案”，不恢复任何旧实验，不改默认。当前可确认完成的是理论收束和历史排重。
