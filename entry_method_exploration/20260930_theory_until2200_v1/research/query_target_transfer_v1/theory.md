# 实例对应保留了什么，以及它没有保证什么

设固定base集合为B，单位查询u的最大内积目标为t(u)。单位训练query v_j配对真实目标t_j=t(v_j)。若在线选择j，则

`u·[t(u)−t_j] = (u−v_j)·[t(u)−t_j] + v_j·[t(u)−t_j] ≤ ||u−v_j|| ||t(u)−t_j|| ≤ diam(B)||u−v_j||`。

若训练目标只是误差ε_j的近似目标，右端再加ε_j。原raw query只是乘正范数，排名不变；base不单位化，diam(B)必须对应raw-IP目标集合。这个标准Cauchy/最优性推导不是新定理，既不假定raw-IP是度量，也没有把余弦相近升级成GT ID相同。最坏界可能很松，HNSW近似查询也不保证选到最近v_j。

把同一实例目标投回原H，令h_j为选定hub，则类似有

`u·[t(u)−h_j] ≤ diam(B)||u−v_j|| + v_j·[t_j−h_j]`。

后一项是训练目标向固定入口集合投影产生的几何损失，非负前提是t_j确为训练query的最优raw-IP目标。QueryTarget1与QueryHub1共享所选j，才可以在实测中隔离这个投影变化。GT10并非简单GT1投影最近邻，因此这一式子不能证明默认画像受损或收益上界。

另一项强控制尤其重要：若对训练目标库做**精确**raw-IP最优选择，则其当前query入口分数至少等于任意query实例迁来的t_j。因而实例匹配不能宣称在该相同目标库的几何分数上超过精确目标侧检索。实际TargetBank1是固定HNSW近似索引，近似误差与费用都须观察。即使目标側分数更高，原生有限pool搜索也不保证Recall更高或NDC更低；已有145反例保留。

本版关注三个具体缺口：跨query目标对应是否有用、投影至小H损失是否重要、查询侧索引的额外费用是否被主搜索节省覆盖。它不是对全部入口的oracle，不学习“最优搜索入口”，也不复用当前query GT。主搜索只完成一次。完整时间减少的必要收支仍是实际主搜索节省超过新增路由/映射费用；分项不相加冒充实际wall。

既有查询复用前作已覆盖大思路。CatapultDB使用在线LSH桶和历史ANN结果；EDBT2026工作面向过滤查询并以历史查询结果提供入口；批查询MST建立当批依赖。本版只是静态独立训练实例对应的受控验证，具体引用与阅读边界见[文献核对](../online_prior_work_2026.md)。不把不同部署/监督合同当作创新证明。
