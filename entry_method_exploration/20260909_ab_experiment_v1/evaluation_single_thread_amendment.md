# 正式评测单线程修订（2026-09-09）

用户明确纠正：“测试不应该是单线程吗”，并要求“最后和别的方法基线对比的时候都用单线程”。本修订覆盖原protocol.md的16线程查询评测条款；原协议、配置、输出保留原始身份，不回写已冻结模型的训练协议SHA。

所有查询评测统一显式`threads=1`，包括Fast20K/30K direct1/3、A+B、全部因素对照和exact诊断。OpenMP、OpenBLAS、MKL及其他数值库线程均限制为1；新入口拒绝缺失或不等于1的线程配置，记录实际OpenMP team大小。正式结果只能从`single_thread_v1/results/`读取，逐批核验线程数，不能拼接或按线程数换算旧16线程QPS。

原16线程评测已停止；完整和中断输出及日志全部保留。服务器重启恢复记录也保留原身份。全部标签和12个已冻结模型复用，所有模型文件与已冻结清单核验；不依据已看见的validation质量重新选择、训练或修改模型。原20K fit、1024 cal、1024 audit、三构建、L64/128、28方法配置/构建、validation10K、held-out10K和三轮换序计时均保持。校准编译检查与audit也重新使用1线程执行。

`config.locked.json`的`threads=16`继续描述当时已完成的离线标签和训练；本次查询配置另落盘到`single_thread_v1/inputs/`并显式设1。`prepare_eval.py`只准备冻结数据，生成的原16线程配置不执行；新的评测控制器复制配置，仅修改线程字段和修订身份。

单线程入口复用同一benchmark函数和原搜索kernel；仅增加线程防护和实际线程记录。count/plain分离、全batch warmup、方法换序、计时边界、全部配对结果及质量门保持。主报告由单线程专用分析入口生成，检查每份结果的配置与实际线程均为1，主报告中明确单线程。

一次只运行一个评测进程；期间不运行标签、训练或其他重负载。启动验收后根据首个完整批次耗时估算余量，按预计完成时间检查，不反复查看实验进度。原45–65分钟估计针对16线程，不再适用；先以保守单线程估计安排检查，再用实际批次时长修正。

这一规则同时进入根目录[AGENTS.md](../../AGENTS.md)与[spec.md](../../spec.md)，适用于后续所有方法基线比较。
