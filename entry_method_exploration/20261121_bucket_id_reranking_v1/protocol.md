# E219 对漏点 ID 粗排并保留高分 B32 尾部

针对 E218 的单表摘要选择不足和 WebVid K100 双表可达性，固定 E217 的全 fit 入口桶、候选表、原 GT10、SPAN4 和 fit-only B32。测试 COCO K100、WebVid K1/K100。查询不需额外训练和 GT。原候选和所选漏点的最终距离仍使用原 raw-IP，原主返回和 B32 公共前缀始终参与最终合并。

## 凑池和粗排

复用三路入口，沿 E217 BKT8 去重，最多 24 个 fit 代表，按原全维点积取前 2 或 4 张预编漏点表（同分取较小代表）。每表按原次序读最多 16 个可用新 ID，全局去重并排除原主返回及原 B32 候选。Q8-2/Q8-4 对这些漏点 ID 和原 B32 可替换的候选尾部逐 ID 计算 512D 对称 int8 量化点积。只在新点粗分严格更高时替换当前最差的原尾部，最多交换 16 个。精算列表仍保留原 B32 的实际候选数，旧项按原序，入选新项按发现顺序。原末位分数和原生严格 Top-K 不变。

逐候选编码使用原向量每行 maxabs/127，按最近整数舍入到 [-127,127]，zero scale 用 1；查询同法在线编码一次。512D int8 代码及 scale/字节和只覆盖 B32-fit 与选表可出现的去重 ID，运行时为直接寻址加一份 int32 ID→码槽映射。使用 AVX512 VNNI 路径或对应整数实现，对真实样本核验符号修正与标量整数积。32/64 表面上是候选扫描上限，四路精算预算与 B32-fit 一致；粗排数量与成本独立计数。

## 对照和判定

同一真实 L184 的 dev/cal 回放以 B32-fit、E216 CACHE、BKT8 最近一表、同两个最近代表各取至多 8 个直接换尾部的 PAIR8 为对照。另外以同 2/4 表、同配额的精确原 IP 排名做 EXACT2/4 诊断，无 GT 选点，评分成本独立，它们只参加回放诊断。记录净救回、损伤、实际原精算数、粗排工作、补点重放两遍 CPU15 单线程时间和模型内存。复核与 E217 三个控制原包。阶段门为 Q8-2 或 Q8-4 在 dev/cal 均达到 B32-fit@L192 且均较同 L 的 B32-fit 正增长。两臂满足时优先较窄的 Q8-2。

通过者在 E217 保留的公共 3072–6143 行（零基，不与 E216 首窗重叠，其他历史曝光存在）测 L176/184/192/200/208/216/224/232/256，CPU15 单线程，每点两遍。同期 GT10、完整 B32、B32-fit、CACHE、BKT8 与入选 Q8。计入入口、主搜、粗排、精算合并及正常批次和六数组生命周期，正式批次无 GT。以该窗实测的最快达标控制比较真实 Recall–QPS，报告相邻 L 和两遍范围。默认替换依据真实同期结果。
