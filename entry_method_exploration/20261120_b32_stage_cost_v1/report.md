# E207 B32 补点分段计时

COCO hard 和 WebVid soft-t1，各取公共10K的前3,072条，真实 K1/K100，L100/200/400。12个配置、48个正常批次和24个分段批次，合计221,184次计时查询。CPU15单线程，每点两遍。12个配置中，额外精算均是最大的残差阶段，占分段残差时间的60.6%–94.2%。K100/L200下，COCO/WebVid的额外精算为14.55/22.01微秒/query，查表去重1.97/2.51，合并5.29/6.07。 E99 GT10 与完整 B32 作为固定比较对象。本轮运行分段诊断并复测同期完整 GT10/B32。

## 完整运行

## 优化讨论

同一配置下，COCO/WebVid可直接复用并排除的主池尾部候选为3.10/0.69个/query，全部候选未过原第K名门槛的查询占36.4%/34.8%。 先在固定 B32 和固定 GT10 下逐项测一次候选向量提前预取与 K100 无通过时直接返回的版本。前者重点对付最大开销阶段，同时继续调用原标量距离核；后者在完全评分确认门槛无通过之后避免建堆及重排。以原候选次序、精确分数和返回位级一致为约束，单开关比较无插桩完整 QPS。

主池重合优先放在 COCO K1/L400 作为探索，该配置平均可略过15.44个精算，占其92.80次额外精算的16.64%。WebVid K100/L200 只有0.69个/query，低于其额外精算的1%。实现时量出识别重合本身的完整代价；L=K 没有保留池尾部。更宽的 visited 重合适合先估计能否低成本保存可复用的精确分数。以上都是本轮数据支持探索的优化方向，完整加速与内存费用须另测。
