# 从完整 QPS 重新推导入口理论

2026-09-22，用户授权至 16:00 的只读理论研究。**本轮未获得新性能提升，也没有通过全部审查的实施候选。** 已将目标、可支付成本、信息价值、决策误差和同召回吞吐连接起来，并把下一问题收窄到一个具体、可停止的假设。

## 1. 最重要的新结论

当前困难不只是“评分器还不够快”。按最近三点曲线，在保持当前 Recall 收益、同 L 非新增成本与默认相同的条件下，可供新增决策支付的平均时间很少：WebVid 约 92/46 微秒，Yandex 约 6.8/6.1 微秒，分别对应 K1/K100。即使在这个思想实验中把新增费用降为零，同召回 QPS 增益也仅约 4.27%/1.72%、1.73%/0.88%。这不是所有新方法的上限，但说明仅压缩当前评分器并不是足够有力的研究主线。

更合理的目标为：**在真实 Recall@1 或 Recall@100 达到 90% 时，最小化完整平均查询时间。** 需要找的是“低成本信息支持的有效动作”，而不只是更准确地预测一个代理分数。当前采用固定底图、主搜索、展开/停止及每配置固定 L；没有逐 query 调预算。

## 2. 当前证据与成本核算

最新完整轻量比较是 [record125](../20260922_knn_three_point_timing_v1/report.md)，不是本轮新测量。它在两集各 4096 条历史曝光 query 上，以 CPU15 实际一线程串行测了双方各三个 L、每点三次：12 个匹配点 Recall 均值全部提高，完整 QPS 全部下降。预测、实际路由、NSG 与输出写内存均计入；四折模型驻留不是最终单模型部署。E103 仍是最近完整五数据集前沿，E118 仍是最近新候选完整曲线。

不用插值，直接在已测三个配置中各选 Recall>=90% 的最快者，结论同样不变：Web K1 默认/候选均 L1000，QPS -19.81%；Web K100 默认 L1250/候选 L1120，仍 -10.27%；Y K1 均 L128、K100 均 L256，分别 -40.52%/-27.88%。这是同一召回要求下的有限已测配置比较，不是两者 Recall 完全相等，也没有新测 L。[离散配置核算](results_v2/discrete_thresholds.json)。

核算方法：分别求两条曲线达到 90% 的 L0、L1，把 `T1(L1)-T0(L0)` 分为 `T1(L1)-T0(L1)` 的综合差额，减去 `T0(L0)-T0(L1)` 的默认预算节省。后一项就是表中的条件可付新增费。**综合差额不是 kNN 单项耗时**，可能混有路由、主搜索和 cache 变化；当前没有能力分别归因。

每组把六个方法/L 点各自三次记录时间穷举为 729 种组合，四组同召回额外耗时范围分别为 Web 509.88-535.35 / 568.53-615.95、Y 277.12-286.48 / 281.68-296.33 微秒，方向没有改变。条件零新增费增益上端也都低于 5%；5% 只是敏感性示例，不是本轮新加的用户准入门。这些范围不是置信区间。完整 [成本表](results_v2/cost_table.md)、[12 点核算](results_v2/matched_L.csv)、[数值与重复敏感性](reviews/independent_verification.json)。

重复敏感性只覆盖已记录端点的计时波动，不覆盖两点之间的曲率/插值误差或新 query 分布。因此微秒预算是有条件的研究尺度，不是严格性能上界或正式允差。

### 不能混用的工作区间

当前 record125 的默认 90% 区间为 Web K1 L800-1000、K100 L1120-1250；Y K1 L96-128、K100 L200-256。Web K1 不能继续套用 E103 的 L640-800：两者 query 与计时批次不同。

本轮三点曲线均不覆盖 95%。单独查看 E103 历史完整默认曲线，Y K1/K100 的 95% 区间为 L200-256 / L400-512，插值完整时间约 748.15/1400.96 微秒；Web 仍不覆盖。它们只能说明历史尺度，不能与本批 Recall 或候选拼接。E103 两 K 的 90% 局部尺度分别为 Web 262.65/333.15、Y 41.65/67.44 微秒/百分点；[独立原 wall 复算](reviews/supplement_verification.json)通过。

## 3. 理论链条

1. **信息要付费。** 完整时间包含获取、评分、路由、主搜索、输出；串行 QPS 是平均时间倒数，不是逐 query QPS 的平均。
2. **动作要算幅度。** 选择需要条件预期损失/收益，不能只看胜率或平均 MSE；正确识别最优入口仍可能因决策费用而变慢。
3. **额外信息要覆盖其费用。** 单组信息的理想价值是观察前后条件最优风险之差，只有超过获取费才值得看；门控费和回退前已发生的费用均不能消失。
4. **表示和误差要进入收益账。** 可实现价值减去动作选择遗憾、额外费用，才是净值；上界 `2epsilon` 和预算迁移 `2(epsilon+delta)` 都有明确前提，不是现有数据保证。
5. **最后仍要满足两个独立条件。** Recall 可行、完整时间降低。单一成本权重可能遗漏非凸策略前沿；离线编译可以直接保留约束，但动作时间可加性和有限样本误差仍需验证。

进一步补上了运行环境限制：缓存动作时间可能受评分器及前后 query 改变 cache 的影响，即使把 cache 并入状态也不自动消除后续状态效应。因此缓存上的决策风险结论不能直接当完整 wall 保证。详细假设、推导和反例见 [theory.md](theory.md)。

实际付费信息价值还可分成“理想信息价值 + 旧决策器遗憾 - 新决策器遗憾 - 获取费”，再扣门控遗憾与所有 query 都要付的门控费。该分解区分信息不足、没有学会利用信息和利用太贵，避免继续把它们统一解释为模型弱。[代数证明与四种必查反例](proof_notes.md)。

## 4. 文献与历史排重

核对了用户指定的 [FrugalML](https://proceedings.neurips.cc/paper/2020/file/789ba2ae4d335e8a2ad283a3f7effced-Paper.pdf)、[RouteLLM](https://proceedings.iclr.cc/paper_files/paper/2025/file/5503a7c69d48a2f86fc00b3dc09de686-Paper-Conference.pdf)、[多专家延迟决策](https://proceedings.mlr.press/v235/mao24d.html)，以及元决策/算法组合的三项直接前作。重点不是搬模型，而是检查目标、费用及保证的条件。RouteLLM 已报告路由开销；不能误说它免费路由，更不能把生成 API 费用尺度移植到微秒 ANN。

“成本敏感选择”“只有划算才追加特征”“离线重、在线轻”都有明确前作。项目内 E25/E36、E104/E105、E117-E120 也分别覆盖了门控、swap、画像摊销、四动作成本树、比较方向、强评分器和目标预算信息。E117/E119 已考虑时间，不能把本轮目标重述当作首次发现成本。[逐项差异表与定理条件](prior_work.md)。

## 5. 保留什么，停止什么

**唯一保留的假设**：从原 GT10 上层结束节点直接查离线动作表，决定原 top3 保留三入口还是某个 rank-single。两集原图 level1 均 52 节点，因此候选状态最多 52；单配置直接索引字节表 815/821 字节，不新增投影、第二路由或全 H 扫描。状态导出和查表仍计费，现有 API 尚不导出该节点。

它尚缺目标预算下对齐的状态、四动作响应、可比成本，以及超过旧六特征/固定动作的查询外收益。小表不证明有效，上层分区不证明同格动作偏好一致，方案也尚未建立论文新颖性。因此状态为 `HOLD_MISSING_TARGET_STATE_RESPONSE_COST`，**实施候选数为 0**。

另一结构“看原 top3，再按需追加真实入口距离”与 E25/E117 和既有算法组合重合，而且没有新的信息收益依据，本轮不立项。不恢复 TargetKNN 参数选择、不升级 MLP/双塔/RL。具体在线操作、同监督控制、停止预测和另行授权的最小证伪外框见 [candidates.md](candidates.md)。
