# E251 四集 B32、老 B64 与 Mixed64 同期复测

固定 E229 的 COCO、Flickr30k、WebVid 2.5M、Yandex official first10M raw-IP 底库、主图、GT10 路由、原版 B32、老 B64 以及各 3,072 个公开查询身份。四集实测真 K1 和 K100。三臂为 GT10+B32、GT10+原全精算 B64、GT10+Mixed64。COCO 和 WebVid 直接使用封存 E245/E243 的 Mixed64。Flickr30k 和 Yandex 采用同一构建规则，从冻结 B32 有序前缀出发，使用扩充的真实训练以及 L176/192/208 实际 K100 遗漏事件，经 E226 原联合贪心编译至最多 64。新增两个表按训练身份、候选覆盖及离线时间登记。

Flickr30k 从原准备好的 profile 角色取 4,096 个源组，为这些查询在原底库重新穷举 exact raw-IP GT100。profile 角色参与过原画像拟合，和原 16,000 条补点训练及全部 5,000 个公开测试源组按源组与向量字节分离。Yandex 从已有 30,000 条 router_train 中按顺序选 8,192 条，精确字节排除原完整 20,000 条拟合、完整 100,000 公开测试与 10,000 validation，原 exact raw-IP GT100 同行绑定。全部评测身份和两个新表数据源在读取新评分之前冻结。历史公开评测窗允许用于复测，测试不参与选表。

采用 E229 的原网格，预先补齐四集低、中、高段和已有代表门槛附近的小档距。详细网格与门槛由运行脚本及冻结配置记录。每个数据集/K/L 上三个方法各跑两个完整批次，CPU15 实际 T1、库线程为 1、逐法串行。按 L 的序号轮转比较先后，第二遍逆序。正常路由、实际主搜、候选去重、原内积全精算、合并及结果对象生命周期都在计时内。独立 K1 的首名对原 GT100 的首名，独立 K100 的结果成员集合对原 GT100。全部正式计时结束后统一评分。保留两遍原始耗时与结果哈希、一份逐字相同的原生返回，以及前 256 条额外标量排序核验，历史同配置返回逐字段核对。

固定召回门槛使用每法最快同期实测达标点，速度取两遍 QPS 算术平均并保留各遍、慢遍对快遍。另报告同 L 救损、实际候选数、实测点支配关系与重叠区间的相同召回折线描述。图为 K1 和 K100 各一张四集面板，每面板只画 B32、老 B64、新 B64。
