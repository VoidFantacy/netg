# E226 B32/B64 双塔直接补点

## 矩阵与目标

COCO hard 与 WebVid soft-t1，真实 K100 的两条补点路线。GT10 三入口、主图及 SPAN4 沿 E222 已验收配置。B32 查三行并集，排除主返回，保持原始行顺序和去重。B64 固定完整原版 B32 的每行前缀，使用 E183 原 K100/L200 漏点 token 继续同一联合未覆盖贪心，每行至多 64。三行最大分别为 96 和 192，实际去重计量。B64 不是嵌入维数。保留各自全精算作为候选池诊断。

双塔以查询和候选原向量分别作独立学习的 512→32 线性映射。候选塔离线编码所有 B64 池唯一 ID，B32 读取同一 ID 映射和代码结构。查询塔只实时投影一次。低维分数选候选，原 raw-IP 精算选中 ID，以原候选顺序和严格 Top-K 规则合并。无辅助搜索。两个池独立拟合，均以同池真正漏掉的 GT100 成员为监督，混合同池原内积分布作蒸馏。PCA 对照取同一拟合集的 32 维正交基，原始向量和去重合同相同，采用配平的精算上限。

## 数据和计时

两数据集复用 E222 第二公共窗 3072–6143 的真实 GT10 返回，按身份或精确查询向量身份拆成 2048 fit，其余进入 cal。WebVid 排除先前窗口内与正式窗口重复的向量及窗口内重复向量，此检测在拟合前完成，保留完整正式窗口。拟合与回放 L176/184/200/224，两个宽度所有 16/32/48 精算上限都保留，记录全精算的候选供给及双塔/PCA 留出结果。固定 48 为完整端到端比较上限，两种学习宽度不因公开测量或回放负例退出正式曲线。正式前 3072 条历史公共查询与本试验 fit/cal 互斥，COCO 核对真实源角色身份，WebVid 绑定 official train/test 来源并核精确 query 字节互斥，不宣称语义身份隔离。为避免测试调参，正式 GT 在两集全部计时结束后才评分。

每集 11 档 L176/184/188/192/196/200/208/224/232/236/244，六臂原版 B32、B64 全精算、B32 PCA、B32 双塔、B64 PCA、B64 双塔。共 132 点、264 批。CPU15 实际单线程同批两遍，旋转和反向轮序。完整 wall 含正常路由、主搜索、候选、投影、精算和批生命周期，加载、预热、验证、GT 和写盘在外。保存实际返回、时间、原精算量及资格口径。正式四个图分别为两集×两种候选池，每张只画 GT10+B32 和对应改进双塔。PCA、B64 全精算和较小精算预算保留在结果表。生产合同按 E99/E211。
