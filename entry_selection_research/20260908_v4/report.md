# 新入口方法调研：用真实搜索收益训练可重复入口的效用决策树

2026-09-08。状态：`RESEARCH_COMPLETE_DESIGN_ONLY`，方法、训练器和性能实验均未实现、未运行。本文是方法推荐，不是性能结论。当前计划统一见[../../s-target.md](../../s-target.md)。

## 1. 推荐与依据

**推荐研究“真实搜索效用驱动的斜切决策树”：离线用全部现有入口的真实搜索结果学习查询分支，在线只沿一条短路径直接输出一个入口。允许多个叶子输出同一个入口。** “斜切”指每个分支判断若干查询坐标的加权和是否超过阈值，而不是只比较一个坐标。它划分的是查询输入空间，原 NSG、base、hub 池和搜索过程保持冻结；不是恢复旧的 base 区域分割方法。

在同一拟合集共同训练非线性query-only重模型与受推理预算约束的树，分别审计搜索收益。重模型是高容量参照，不是理论上界；树直接优化实测收益，不必复制重模型的唯一入口 ID，教师失败也不能否决成功的树。这个选择把研究问题拆成两件可证伪的事：现有输入中是否有可学习信号，以及轻量决策结构能保留多少信号。

推荐理由来自本地缺口和算法适配，而非“树”或“蒸馏”新颖：

- 把Fast的ANN检索改成同画像的精确检索，收益小且方向不一致；这不证明几何模型类或真实搜索效用接近上限。在已完成的双数据集诊断中，即使提供真实 GT1 basin，仍比当前全 H 单入口 oracle 低 4.80–13.07 pp；oracle限定给定 H、L 和 Recall@10，免费选择，不能当部署点。
- exact C8 内完美选单入口仍损失 3.16–6.66 pp。因此新树的每个叶子从全 H 动作池选入口，不依赖 Fast 先给出 C8/C32，也不预先强制 anchor 或三个入口。
- 一个入口可能适合几块分离的查询区域。多叶可选同一入口，允许其选择域成为多个多面体的并集；这只是表示能力，不证明数据确有这种结构或 20K 样本足够学到。
- 分支训练直接支付选错后损失的 Recall。两边一样好时不强迫区分，避免为了匹配某个任意 tie-break ID 浪费容量。

原始诊断及其统计边界见[Fast报告](../../fast_router_diagnosis/20260908_v1/report.md)、[正式分析v2](../../fast_router_diagnosis/20260908_v1/analysis/v2/analysis.md)。这些证据支持换研究目标和决策结构，尚不能证明新方法会改善 QPS。

## 2. 为什么不是重做旧方法

本轮重新读了旧训练器、标签生成、正式配置及结果；详见[本地失败审计](reviews/local_failure_audit.md)。

| 路线 | 已有内容或失败边界 | 本次真正改变的部分 |
|---|---|---|
| Fast | GT1 几何 basin 的均值画像，在线内积近邻 | 用真实搜索动作收益学习查询分支，不继续拟合相同几何标签 |
| 旧 NETG / GATE | 真实 probe 监督、复杂入口侧映射、在线 raw-query 与预计算入口向量内积；旧 NETG 正式 probe L=300 | 非线性 query-only 重参照；部署树可让同一入口对应多个分离区域；直接对应原 kernel 的 K10/L64、128效用 |
| 旧 static utility ranker | 已用真实 Recall/NDC、软标签、成本权重、query–hub 交互及 Fast top32 | 改为全 H 可选动作、路径决策和真实子树损失；“换成真实标签/加softmax”不是新点 |
| finite-beam v2 distillation | query 64-NN 的局部效用估计，top8真实监督；四点utility差95%区间跨0 | 不再靠局部 query 邻居搬运效用；直接拟合非线性参照与可重复叶动作的树 |
| 旧 P3 分层 | 对 base/图建区域，GT集中度/门户与区域候选池，搜索收益 NOPASS | 新树只选既有入口；不切 base、不改变图、不建区域搜索池 |

“全 H 探测”“真实搜索标签”“离线重、在线轻”“成本敏感”“蒸馏”单独拿出来都不是新贡献。当前可辩护的研究假设是：**直接对当前搜索 kernel 的收益训练可重复动作的查询决策区域，能否在单路径推理预算内获得旧固定内积表示没有获得的样本外收益。** 它是新的本地方法候选，未声称学术首次。

## 3. 文献比较后为何选这一条

本轮查阅原论文与作者代码，来源和版本见[入口文献审计](reviews/graph_entry_literature.md)、[策略编译文献审计](reviews/policy_compilation_literature.md)。

| 备选 | 对本任务有用的机制 | 当前判断 |
|---|---|---|
| 学习入口/节点 embedding，再 ANN 路由 | 离线复杂表达、在线内积便宜 | GATE/旧 NETG 已有强重叠；仅加强入口侧模型不能改变 raw-query 线性评分的基本边界 |
| 重教师到小 MLP / 双塔蒸馏 | 检验质量可预测性，测压缩损失 | 保留重教师作为参照；泛称蒸馏没有解释旧失败，为主推荐还缺具体结构和损失 |
| Filter Tree | 全动作代价转成按代价差加权的二分类，单路径预测 | 有价值的对照与损失启发，但一个动作仅一个叶子且分支线性时，其选择域仍凸；不作为本次主方案 |
| 直接效用斜切树，允许动作重复 | 叶子按总收益选入口；分支按当前两棵子树的真实收益差反复训练 | **主推荐**。在线成本可直接约束，机制和失败位置都能独立测量 |

[Learning to Route in Similarity Graphs, ICML 2019](https://proceedings.mlr.press/v97/baranchuk19a/baranchuk19a.pdf) 已允许复杂节点侧模型离线计算，查询侧为 identity/线性投影，并针对预算训练。作者[NoProjAgent/PrecomputedWalkerAgent代码](https://github.com/dbaranchuk/learning-to-route/blob/53ddfded604a4ad4c11de4e2a9672d515a014378/lib/walker_agent.py)进一步说明线性变换转移到节点侧也是已有做法。它学习逐跳路由，不等于本地固定搜索过程的单入口 Recall@10 效用，但不能把其已有的计算分工重新包装为创新。

[TAO, NeurIPS 2018](https://faculty.ucmerced.edu/mcarreira-perpinan/papers/neurips18.pdf) 提供对固定树交替优化分支和叶子的框架，允许同一类别出现在多个叶子。本文借其训练结构，将原分类损失改成逐查询、逐入口的实测搜索损失；这部分是拟议适配，并非作者代码已有 ACSG 实现。TAO本身没有全局近似保证。[作者页面与公开代码](https://faculty.ucmerced.edu/mcarreira-perpinan/research/TAO.html)只读核查，没有安装或执行。

[policytree作者文档](https://grf-labs.github.io/policytree/)支持用每行动的收益矩阵学习策略，但其浅树枚举方法不能直接扩成深度10并宣称全局最优。本地有全动作搜索标签，第一阶段也不需要把观察数据的因果估计、逆倾向加权或在线探索引入问题。

[Filter Tree原稿](https://mi.eng.cam.ac.uk/~mjfg/local/Projects/filter_tree.pdf)的算法使用两个**实际子树输出**的代价差作为训练权重，而非比较两边的免费oracle最优。其 `ceil(log2(H))` regret系数适用于普通0/1多分类推论；一般成本敏感定理含代价差权重和。不能把它移植为本方案的Recall保证。下载副本见[sources/filter_tree](sources/filter_tree)，本轮未找到可确认的原稿作者实现。

## 4. 方法如何工作

完整数学定义、训练步骤、推理契约和风险见[method.md](method.md)。最小过程是：

1. 对拟合查询，从每个现有 hub 真实运行原单入口搜索，记录不同 L 下的 Recall@10 和 graph NDC。保留完整动作向量与全部同分入口。
2. 用 query-only 重模型预测这些收益。开发查询的 GT、probe、完整轨迹不能作为模型输入；否则成功只说明额外信息有用，不说明在线输入可预测。
3. 学一棵树。每个叶子从 H 个入口中选择对到达它的训练查询总 Recall 最高的入口。每个分支比较：把查询交给当前左子树、右子树，最后会选什么入口，各自真实 Recall 是多少。收益差越大，分错的权重越大。
4. 反复更新叶子和分支，只接受真实训练目标不变或变好的合规更新。多个叶子可以选择同一个入口。树的深度、每节点非零权重数和叶子最少样本数都受约束。
5. 在线只读取 query，走最多10次轻量线性判断，取得叶子中的 base ID，调用一次原搜索。不运行教师、不生成C8、不扫描全部H，也不查看当前query的GT。

这里“轻”有明确的结构依据：深度10、每节点64个非零坐标时最多640次乘加；允许全维时，WebVid/Yandex分别最多5120/2000次乘加。还必须支付索引读写、分支、入口初始化、模型缓存和主图搜索，不能把这些操作数直接换算成QPS。若原查询向量尚未生成，编码成本也必须单列/纳入应用边界；本地ANN比较共享已有向量。

## 5. 先证明什么，失败时怎样停

[minimum_gate.md](minimum_gate.md)给出了拟议样本分离、模型范围、资源上限、产物与停止条件；它尚未冻结为可执行实验。阶段顺序为：

- **标签/实现门槛：** 原 kernel、输入身份、真实入口消费、count/plain一致；任一失败先修实现，结果不进入方法结论。
- **可预测性：** 重参照与树在同一拟合集训练，分别看是否在未参与本轮拟合和调参的开发审计集超过 Fast 单入口。教师失败仅否定该模型/样本设置，没有一般不可学习结论，也不删除成功的树结果。
- **轻量保留：** 树是否保留足够重模型增益；同时比较直接效用训练与复制教师唯一ID的同结构控制，避免把收益误归因于“树”。
- **部署收益：** 将整个树推理纳入原搜索纯wall，比较Fast1与Fast3及强基线；最终仍要求双数据集、相邻工作点、三独立构建、尾部与冻结后的held-out10K×3。

重模型好、树不好时，问题定位在学生容量/训练；二者都不好时，优先检查表示和数据。树选不到好入口但其实际输出集合含好入口时，问题在分支预测；树输出集合本身漏掉好入口时，问题在叶子/动作容量。所有oracle只作损失拆分。

## 6. 仍可能失败的原因

20K查询可能不足以学习815/821个动作在高维空间中的真实效用；搜索的有限候选池还会制造难以平滑预测的变化。深树顶层误判会排除整片叶子，单路径没有纠错。多叶重复动作消耗叶子数，最少样本限制还会减少可输出的不同入口；“全H作为动作候选”不代表树覆盖所有H。交替训练容易落入差的局部解，训练单调改善不保证开发效果改善。稀疏化可能删除有用维度，密集树可能增加缓存与分支成本。

因此本轮结论是**值得做一个有界的新方法检验**，不是宣布找到突破上限的办法。没有新训练、性能结果或方法GO，也没有恢复旧实验。
