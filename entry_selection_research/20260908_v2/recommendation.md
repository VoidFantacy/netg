# 唯一推荐：固定主入口的真实三入口组合选择

2026-09-08；`DESIGN_ONLY_NOT_IMPLEMENTED`。这是优先证伪问题，不是已经有效的新算法。推荐条件、实验限制及对照见[gate草案](minimum_gate.md)；既有失败分支不重开。

**保留Fast主入口a，用一次Micro-HNSW拿同一view的C8，从另外7个候选中选两个补入口。** 主方法固定三个入口，只枚举21个`{a,b,c}`。另将含a的一至三入口29个集合用于离线诊断，判断“少用入口”和“改入口组合”的差别，不将可变m加入主模型。

## 为什么选择这一项

A改变候选池，B改变单入口查询匹配，C改变实际决策/监督单元，三者不是模型大小的差别。当前没有证据显示优先重建池更有价值；B的top32版本、单标签画像、残差画像和历史效用蒸馏均已有失败边界。C保留池、表示和短名单，只检查旧单入口标签遗漏的条件交互，归因相对清楚。

另外两项的具体版本也应可被比较，而不是抽象口号：

- **A：同预算的搜索效用候选覆盖。** 固定候选宇宙P（现H加仅由QGT/fit预定的额外真实base节点），预先测fit query的single搜索。选择`|H'|=H`以提高`mean_q max_{e∈H'}[R(q,{e},L)−0.05D(q,{e},L)/D_F(q,L)]`，可用固定次数贪心作离线近似；最大值仅是“每query理想选一个入口”的代理，不保证在线能路由到它或三入口有效。还须为H'重建同20K画像和一个Micro-HNSW，并与同样H数量的原QGT、几何/PSP思想池比较。CPU实现可行性取决于标签矩阵/候选数；20K×约千候选×两L会达到数千万次搜索。rawIP标签保留范数，但若只按几何覆盖可能对WebVid/Yandex产生相反偏向。新颖性需要证明何种可路由效用覆盖超越已有候选方法，目前没有这个证据。因此最小gate只查有限扩展池的oracle空间，不直接建设A。
- **B：同短名单的独立搜索偏好排序。** 固定H、p_h和C8，学`f(q,e,L)`拟合single Recall/NDC效用，以可加分数选两个补入口并保留a。目标可以是固定ridge回归或旧listwise损失；本设计只保留前者作为确定控制，不比较损失。标签约`Q×8×2L`，在线单HNSW加候选特征/排序，CPU与rawIP兼容而不读取在线GT。它在20K条件下可能比旧10K更稳定，但没有证据支持把增加样本当机制创新。GATE、旧NETG与本地static/atlas使其新颖性和成功依据最弱；失败风险是静态输入不足、短名单漏选与single/联合部署错位。

旧 `CurrentHub_Diverse_Top3_GreedyProxy` 从独立single的GT命中集合选三再重放，没有枚举三入口搜索。旧ranker则预测single utility后排三个。C直接评价同一次共享visited/容量L搜索的结果：

`R(q,S,L) = |Search_G(q,S,L) ∩ GT10(q)| / 10`

`Δ(q,e | S,L) = R(q,S∪{e},L) − R(q,S,L)`

Δ可以正、零或负，不能假定单调/子模。主模型直接比较整组动作，避免用逐步贪心的局部最优冒充21动作最优。允许计算上述差值作机制描述，但实际标签来自真实联合搜索，不来自single命中相加。

## 一个有界的可预测性模型草案

每数据集一套系数，两L共享参数和固定超参数；不要求两数据集学得相同权重。小模型只是检验输入是否含足够信号，不是论文贡献。

1. 复用同20K的p_h和原始h；C8、anchor、索引seed/M/ef和tie规则固定。在线不做probe，不加view，不用query近邻历史索引。
2. 对候选取`p_h·q̂`、`h·q̂`、hub norm及gate特征表规定的分数乘积。第二个分数保留hub范数；q̂只作路由特征，真实搜索仍用q和raw h。为固定浮点语义，特征阶段重新计算8个prototype点积和8个raw点积，共16次另计routing NDC；搜索中重新计算种子距离也照计，不能假定跨模块复用。
3. 训练前生成raw-hub/prototype的pair cosine表，查询只对C8的组合查表。hub-pair表最多`2H²`个float32（H=821约5.39MB，十进制），生成约`O(H²d)`并入离线成本；没有新图邻接或运行轨迹输入。
4. 小模型以固定40维的单项及成对聚合特征预测动作效用。包括query–entry分数与候选pair相似度的乘积等条件项；采用一套固定ridge参数，具体完整特征表在gate中。不能从pilot增加特征/改正则或再换模型。
5. 标签相对同query、同L的Fast3：`u(q,S,L)=R(q,S,L)−R(q,F3,L)−0.05·(D_G(q,S,L)−D_G(q,F3,L))/max(D_G(q,F3,L),1)`。GT、D_G和Fast搜索输出只在标签/评测层可用。系数0.05只是预设的graph工作量代理，刻意沿用旧ranker成本权重以便对照；不是延迟校准，也不是创新。
6. 在线计算21个动作的预测差，Fast3动作固定为0；仅有严格正分才替换，否则返回Fast3。同分优先原Fast3，再按补入口ID词典序。预测并不保证安全回退，实际误换必须计入newly_harmed。

必要的可加对照使用**相同C8、相同single廉价特征、相同fit查询和正则**，只学single utility，再将两个补入口独立打分相加。不用旧10K模型权重污染新协议。另加一个以真实三入口标签训练但去掉pair项的消融，区分“换标签”与“成对特征”的贡献；该消融只在512 audit的已保存动作结果中评估，不增加G3曲线/扫参。

在线额外开销约16d个点积MAC、至多28对候选的两张相似度表查表、21×40量级特征/打分操作，另有shortlist返回、排序与内存读写。这只是操作数量估算。是否低延迟由独立pure wall确认，不能由FLOPs或HNSW的ef相同推出。

## 新颖性应该怎样表述

不能当创新：学习入口、冻结底图、小导航索引、真实搜索监督、廉价推断、多个入口或图感知。GATE、旧NETG/Fast和本地失败分支均覆盖其中多项。SOAR等也已有“补充项应修补主项失误”的思想；分片冗余的理论不能移植为共享beam入口保证。

可以检验的差别是：**在有限历史query、固定单view小短名单和原始IP有限beam下，真实组合交互是否存在、是否可预测、以及同成本可加选择是否无法实现该收益。** 只有这三层同时成立，才可能进一步形成方法贡献。当前查阅集合中未见完全相同契约，不等于已证明原创；原文与代码覆盖缺口保留在[比较表](related_work.md)。

## 主动反对这项推荐的理由

| 风险 | 为什么实际可能发生 | 什么结果应停止 |
| --- | --- | --- |
| 没有新增在线信息 | pair几何只是已有向量的组合；query特定远处路径竞争不可见，旧static/topology失败对此有警示 | oracle有效但固定小模型/去pair对照之间无稳定差，停止，不扩MLP/GNN |
| 模型只学到总体最好的入口数/排名 | Fast1/2可能已经占优，或只需固定选rank1/4/7 | 固定m3不胜可加/固定规则，撤销“学到交互”的解释 |
| anchor约束太强 | 主入口也可能误路由，所有含它的动作都劣 | 预定无anchor诊断显示空间主要在外面，只记录ANCHOR_LIMITED，不当场放开anchor |
| 短名单遗漏 | C8仍用单平均画像；全池好入口可能根本不在C8 | 全池single空间明显而C8 joint余量不足，关闭C8组合版本，另提短名单研究 |
| 数据不够 | 20K与约800 hubs下，pair可能非常稀疏；2048标签只做小门槛 | pilot效果集中在少量重复目标/拟合常见pair，不能主张泛化或增加新样本补救 |
| 成本淹没收益 | 旧Multi-view已证明routing可吃掉graph节省；pair表访问也会耗cache | 全cost实测无匹配/未达门槛则NO_GO或INCONCLUSIVE，不用同L Recall辩护 |
| 偏离raw IP | 路由cosine隐藏Yandex范数效应，WebVid范数特征又近乎常数 | 两数据集机制方向冲突时收窄，不归一化搜索向量去制造一致性 |

若A的限定池诊断更强，或B已经达到同成本效果，应承认本次唯一推荐被推翻；不将三个方向同时排队执行。
