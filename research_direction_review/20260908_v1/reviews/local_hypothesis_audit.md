## 3. oracle、λ 对照与局部尺度的关键限制

**GT 区域占比 oracle 不是最优搜索调度 oracle。** 它只知道终点 GT10 分布，并按固定规则选择四叶区、再分配静态容量；它不知道当前前沿中哪个非 GT 节点能以较低代价打开后续命中，也没有搜索所有可行的入口、容量和扩展策略。真正的搜索效用还取决于到目标的路径、距离排序、已见状态、剩余工作量与跨区域中间节点。即使输入真实占比，所用规则仍可能不合适。M4 因此也不是 Recall 上界：全局 top-K 会接收所有已计算节点，跨区访问没有被删除。

**同 L 不等于同实际成本。** 例如 P2 WebVid L64，同 oracle route 的统一池总 NDC 为1064.6325、QPS 30699.0933；区域池为1473.6620、QPS 21352.2572。质量增益中有多少来自多做距离计算，现有同 L 对照没有回答。更多 NDC 也不自动否定方法，因为队列/内存/并行实现可能使单位 NDC 的成本不同；最终仍须看同机实际 wall。把 NDC 单独恢复为正式硬 gate，同样不合适。

**λ1−λ0 是完整 GT 结构分支的对照，并非只改一个权重的纯消融。** 共同初始化是有效控制，但 `/refinement/destination_candidates` 明确规定 λ1 增加同 GT10 查询的候选叶，λ0 完全 GT-free；两分支之后各自形成标签、门户、oracle 四叶区和整数容量。当前对照可靠地否定了这个完整分支的预期收益，不能把差值唯一归因于 λ 权重、某次移动、某一门户或切边增加。要声称纯目标消融，未来必须另外控制候选集合；这不构成现在重扫 λ 的理由。

**λ=1 的全局归一化没有带来局部平衡。** 已完成的严格界和代数证明说明：固定节点、当前状态、候选与可行性，当前更新先比较整数 ΔS，再比较 ΔC；全部 fit 目标满足该界，unseen 的 ΔS 恒为零。图仍影响候选与同 ΔS 的排序，容量和更新顺序仍有效。这足以纠正“两个归一化项在局部移动中同等权衡”的解释；不证明全局字典序最优，不重建真实移动反事实，也不证明该优先级导致 Recall 下降。物理图没有删边，不能把切边项增加写成图连接被破坏。

**P3 尚未测试层次预测。** oracle 全局选四叶区，没有运行 P4 的粗→细推理。16×16 此时主要是分区组织与容量约束；“层次预测无效”“层次路由成本无法接受”均不是本轮已知结论。现有监督目标也没有直接奖励达到 GT 之前的搜索进展，所以集中度改善不蕴含有限容量下的命中改善；这是目标与搜索的一致性问题，不是证明所有目标引导都无效。

## 4. gate 应保留什么，应改哪一层计划

原 gate 的执行没有因当前负结果而变错：它按预先固定的 λ1_greedy3、两个数据集、两个 L 判定 NOPASS，避免了事后选 λ0 或有利单格。原结果和停止决定必须保留。应修改的是**下一版本的研究依赖关系**。

| 当前约束 | 审查意见 |
| --- | --- |
| 数据身份、GT/split 隔离、纯 wall、真实 API 无 GT、独立输出、P1 后才判算法、独立构建及冻结测试 | 保留。这些决定证据是否有效，不限制科学路线 |
| P2 允许“同 L oracle Recall 正收益＋定位差距”后即进入更复杂表示 | 当作一次有界探索授权合理，但不能等价为效率机制成立。下一版先检验等实际成本潜力 |
| P3 必须 λ1 在四个同 L 点都优于 λ0，才继续整个长期目标 | 对原版本的特定贡献有效；它不是所有有效检索方法的必要条件。与最终同 QPS/Recall 目标并不等价，不能永久绑定长期目标 |
| 固定 16×16、硬大小上限、top4、25%共享、每区最少4、静态概率配额 | 都是待检验实现假设，不应在新计划中被当作成果定义。当前组合暂停，不能仅改名称继续同类扫参 |
| 强基线、实际成本前沿到 P5/P6 才集中验证 | 应前置基本实现和小曲线。尽早知道可靠 Fast及适配有效的强实现已能达到什么成本/质量，避免代理指标推动复杂化 |
| 必须证明“正确区域/门户仍不可达”才能考虑改图 | 不应把有限预算瓶颈误写成不存在路径。未来改图路线需要独立的、支付距离/空间成本的路径改善证据；当前无此证据，也不能以本次失败自动触发 |

统计上，要求四格均正是原贡献范围的严格选择，不应简单叫“多重比较错误”。本轮普通查询 bootstrap 只刻画给定图、fit、初始化和已使用 pilot 下的差异，未检验三构建或正式泛化。区间含零应记未证实，不能自动增种子/工作点重跑。双数据集稳定改善的最终要求不应为美化本轮结果而放宽。

## 5. 可保留资产与已关闭分支

可保留：可靠 Fast/paired20K、冻结图与输入身份链；无 GT 的搜索接口、独立全局 top-K、容量/调度代码作为实验组件；纯 wall/count/trace、真实入口消费和同入口 parity；可重放的固定 trace；确定性严格分区与离线门户 probe 缓存；完整负结果、目标支持/集中度诊断及精确局部尺度推导。保留组件不等于保留方法有效性 claim。当前 CPU baseline 环境可复用，但依赖安装通过不代表基线已经复验。

不能重启：旧 Multi-view/E1b 与共享-alpha attention、静态 utility/probe-reroute/BTG/residual modes 的原失败配置；本次 λ1 硬分区完整组合；把 λ0 换成“新主方法”、调 λ/seed/区域数/温度掩盖失败；在 P3 失败后直接训练原 P4。WebVid概率容量几乎等于均匀的发现只解释已有差异，不能自动授权温度扫参。

不能扩大为禁令：任何使用 query/target 信息的未来方法、全部固定图控制、全部门户优化、全部层次预测。新路线必须有不同且可反证的机制、成本根据和独立协议；是否有文献层面的新意由本轮并行论文审查决定，本地负结果不提供新颖性证明。

## 6. 唯一建议的下一次小 gate：同实际成本下，现有目标信息是否留下可用空间

**只回答一个问题：已观测的 GT 占比条件下的质量增益，在对照也获得相应实际计算时间后是否仍存在？** 这是下一版本的成本筛查设计，不是重开 P3，也不是宣称拥有最优调度 oracle。不先重分区、不训练 P4、不改 λ、不加边。

1. **固定对象。** 使用原 P2 的64个仅图区域、固定门户与已冻结 route 规则；选择它是因为它在 GT 分区修订前已预注册，而非选取 P3 中较好的 λ0。继续同20K fit、同10K历史pilot、同图/raw-IP/线程/全局结果规则。全量pilot避免按既有收益挑查询；不能称新测试集。所有真实成本都使用新的隔离输出。
2. **先完成强实现基线契约。** paired Fast为必需参考；并行文献审查选定的一个强基线须先完成 raw-IP、同数据/线程、真实路由及计时验收。原方法与受约束适配分开说明。若基线不兼容，记录原因，不能悄悄降级或据缺失基线宣称整体胜出。
3. **极小固定矩阵。** 对同一 GT 占比 oracle route，区域概率池只测 L=64/128，统一池只测 L=64/96/128/192；Fast和已验收强基线使用预先固定的对应工作点。六个同 route 核心点是为了给统一池支付相应成本的机会，不能从原两个 L 的折线插值得到比较，也不自动追加更有利的 L。oracle 适配仍在评测层，GT 查询成本不进入部署点；两个 oracle 队列共享相同的免费标签条件和实际入口。
4. **以 wall 作主比较。** 在一个共同的交错顺序中测独立单方法整批 wall，预分配与评分边界复用 P1，count/plain ID核对；报告 routing/graph/total NDC、实际入口和存储。对每个区域池工作点，在实测统一池点中找 QPS不低于它且Recall最高者，bootstrap中重做可行点与比较点选择。不存在可匹配实测点、计时无法区分，均记 INCONCLUSIVE，不插值、不把相同 L 当成本匹配。NDC用于解释是否多做了工作，不能代替wall或当作免费计算。
5. **筛查规则先冻结。** 建议选定一个主族：同 QPS Recall。两数据集两个区域池工作点都需达到原长期目标的 +1 pp 量级、查询配对区间支持正差，并且相对真实强基线仍有正的性能空间，才值得研究新的低成本搜索控制。采用何种计时不确定性和比较族校正，应在运行前写入新协议；不能把五次 timing 当Recall样本。此门槛是 pilot 继续条件，不替代原正式三构建/冻结测试。新增真实预测器的成本尚未支付，oracle过关也不构成部署GO。

这个 gate 的结果应决定路线，而不是把任何结果解释成继续当前层次方案：

| 结果 | 允许的解释与后续方向 |
| --- | --- |
| 区域池在同实际成本下仍优于同 oracle 统一池，且有相对强基线的空间 | 当前静态控制家族有值得解释的空间；之后才设计保留规则与调度的独立控制，评估一个低成本、无GT的实现。不能直接恢复原 P3/P4 |
| 只有 oracle统一池有空间，区域池无额外收益 | 空间可能来自入口条件，当前硬配额保护没有获得成本支持；研究方向应从新证据重新选择，不复活旧Multi-view |
| 两者都没有预定量级空间，或收益只在多花时间时出现 | 关闭这个固定表示/入口/队列家族的效率路线；不追加同类参数。不能据此否定所有固定图策略，因为该oracle从未是最优调度oracle |
| 缺匹配点、CI或计时精度不足 | INCONCLUSIVE；保存界限，不自动展开扫描或训练大模型 |

本设计不需要逐查询 hindsight 选策略。若综合研究另行采用这种诊断，必须在运行前固定有限候选策略，明确它只是这些候选中的乐观参考；它不是所有搜索策略的上界，不是可部署收益，也不能省略策略选择成本来宣称真实方法获益。

本小 gate 不把“改图”设置为失败后自动执行的答案。只有另有受控 trace 支持具体的有限预算连接瓶颈，才考虑独立改图设计，并支付附加距离/空间、设置等边数几何对照。未发现有限 trace 路径不能证明不可达，也不能把本次硬区域失败当成图不可达证明。
