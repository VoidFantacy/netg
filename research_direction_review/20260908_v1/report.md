# ACSG 方法与研究方向复审

2026-09-08；依据当前本地 P2/P3 证据及截至当日可得的一手论文。结论是：**当前具体方法存在目标与搜索成本不一致的问题，计划需要实质修改；尚无证据否定查询分布感知的图搜索这个研究方向。** 先停止当前固定硬区域组合的默认推进，把实际成本筛查和强基线前置，再决定下一种机制。本轮完成文献与设计审查，没有运行新实验。

## 1. 方法的问题在哪里

当前方案把一条尚未证明的链条写成了架构：让正确答案集中在较少区域 → 预测区域占比 → 按占比分配候选容量 → 更快找到答案。已有证据支持第一步的训练指标，后面的传递失败。

- **代理目标改善，搜索没有改善。** P3 中 WebVid 训练 GT10 平均跨区数从 4.333 降至 2.603，但预定主对照 Recall@10 在 L64/128 分别下降 0.866/0.790 个百分点；Yandex 未证实改善。WebVid pilot 的目标集中度也有部分传递，损失却主要来自训练中见过的目标，不能只归因于未见目标的泛化问题。
- **原 oracle 没有回答效率问题。** 它知道正确答案在哪些区域，却仍按固定规则选择四区、分配容量；它不是最优搜索策略。P2 同容量 Recall 上升，同时更多计算、运行更慢。例如 WebVid L64，同 oracle 入口下统一池约 30,699 QPS，区域池约 21,352 QPS。普通搜索若获得同样时间，差距是否仍在，尚未充分检验。
- **目标尺度也有实际问题。** 当前 λ=1 的局部比较，在已核验条件下先按训练目标分散变化排序，再按切边变化排序，并不是两项局部平衡。但这不证明该尺度导致 Recall 退化；两分支还改变候选生成、区域、门户和路由，不能把完整分支差值归因于一个权重。

这些结果足以接受当前组合的负结果；P1 正确性检查覆盖了主要已知实现风险，继续泛泛归咎于 bug 没有证据。同时，P4 层次预测没有运行，不能写成所有层次预测均失败。数值、检查范围与限制见[本地假设审查](reviews/local_hypothesis_audit.md)和[原始研究判断](../../hierarchical_target_search/20260907_v1/overnight_20260907T155400Z/current_findings.md)。

## 3. 大方向保留到哪一层

**保留问题：在有限历史查询和 CPU 成本约束下，利用查询分布减少图搜索中的无效工作。** 保留 Fast、冻结数据与图、正确搜索组件、纯计时/计数/trace 和负结果证据。

**暂停具体组合：16×16 硬划分、GT10 集中度主目标、固定 top4 与静态占比配额、单门户覆盖代理驱动的完整方法。** 不沿旧 P3 调 λ、换种子、加门户或进入原 P4。旧 Multi-view、静态 utility ranker、probe-reroute 等关闭边界也保持。

**下一候选机制由搜索成本证据决定。** 终点在哪不等于怎样低成本走到终点；某区答案多，也不必然值得再给一单位工作量。应区分首次命中前的成本、首次命中后的收集成本、候选淘汰/终止所失去的机会。首次命中仅是在独立 trace 结束后关联 GT 得到的离线诊断标记，不是可直接在线使用的信号，也不等同于已经到达其余答案的可搜索邻域。

固定图上的停止/保留/调度可作为优先研究对象；“根据 query 分配工作量”本身已有前作，也不能直接复活旧预测器。改图只作为独立候选：必须有受控证据说明具体路径瓶颈，随后与相同边数、相同空间的普通边对照。复现一个缩小的 RoarGraph/NGFix 不是自动获得方法新颖性。

## 4. 计划如何修改

新优先级和唯一小筛查详见[修订计划](../../s-target.md)。最高优先项是**成本校准**：先验证强基线可比性，再冻结原 P2 的图区域/门户/入口条件，给统一池更多普通搜索预算，检查 oracle 区域池在匹配实际 QPS 后是否还有预定量级的 Recall 收益。这只补齐旧证据缺口，不修改原 P3 gate，也不承诺继续区域方法。

该筛查预定统一池/区域池 QPS 比在 [1.00,1.02] 内作近似匹配，超差或无匹配记 INCONCLUSIVE，不能把统一池未用完的时间预算误算成机制空间。筛查失败：关闭所测固定表示/入口/队列家族的效率路线。通过：只证明有限实测策略与上述容差下有值得解释的空间，仍须给出低成本、无 GT 的机制及独立对照。测量不足不自动扩扫。无论结果如何，都不能把 GT 占比 oracle 当成所有固定图算法的性能上界。

外部强实现的可比性应在新方法构建前解决：同图机制比较以 paired Fast、同入口统一池及通过新契约验收后的 GATE 受约束适配为参照；另设完整系统比较，优先核验 PyANNS 这类优化充分的通用实现，并与 RoarGraph/NGFix 等改变拓扑的方法分开报告。若原始 IP、样本限制或计时口径不兼容，明确记缺口，不用论文速度比替代本地实验。

最终验收继续要求双工作负载、同 Recall 的 QPS 或同 QPS 的 Recall、全部在线成本、三独立构建与冻结后的 held-out 10K×3。pilot 不是新测试集；validation 此前仅做过完整性检查，没有参与性能选择。本轮未打开原始 query/GT/base/图，也未恢复已关闭的夜间执行。

复审前文档与状态保存于 `source_before/`；原实验报告、gate 与 state 保持。当前完成的是研究判断与计划修订，尚未得到一个通过实验的新方法。
