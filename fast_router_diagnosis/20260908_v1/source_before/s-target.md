## 当前方案：入口点怎样选

**保留 Fast 选出的主入口，学习另外两个入口怎样与它配合，最终将三个真实数据点一起交给原 NSG 搜索。** 目标是改善完整路由加搜索的 Recall–QPS 前沿；Fast v1仍为已验证基线，固定原图、原始IP和搜索语义。

### 在线流程（待实现）

1. **沿用入口池与查询画像。** 复用独立QGT5K构造的真实base hubs `h`，以及同20K历史查询形成的画像 `p_h`。画像用于查询到入口的匹配，最终送入NSG的是画像对应的真实base ID。当前版本固定一个Fast view，不重建候选池。
2. **一次路由取8个候选。** 用Micro-HNSW搜画像，按匹配顺序得到 `C8=[a,e2,…,e8]`。`a`是Fast排名第一的主入口，原Fast3为 `F3={a,e2,e3}`。wrapper须验收同参数top8包含同Fast top3且主入口一致，不能只由ef相同推断。
3. **保留a，枚举其余7个中的两个。** 候选动作是 `S={a,b,c}`，共 `C(7,2)=21` 组三入口。主方法固定三个入口；含a的一至三入口共29个集合只用于离线诊断。
4. **预测每组相对Fast3的收益。** 固定40维ridge线性模型，使用查询与画像/真实入口的匹配分数、hub范数、入口间相似度及其交互，并以搜索候选容量L作为条件。每数据集一套系数，两训练L共享；输入和正则事先固定。入口不相似只是特征，不是“越分散越好”的硬规则。
5. **选择最高正分，执行一次搜索。** Fast3的预测差固定为0；最高预测分严格大于0才替换，否则仍用Fast3。同分优先Fast3，其余按补入口ID词典序。选中的三个ID初始化同一次原NSG搜索，共享容量L的候选池和visited。

```text
查询q → 单次Micro-HNSW → C8，固定主入口a
      → 枚举21组{a,b,c} → 小模型预测相对Fast3的收益
      → 最高正分组合；无正分则Fast3 → 一次原NSG搜索 → top-K
```

21组在线只打分，不各跑一次NSG，也不先跑Fast取得其真实结果或成本。主入口是必保留种子，不保证最先扩展，原kernel仍按真实query–base距离排种子。预测回退不保证实际Recall不下降，误换造成的损失必须记录。

### 离线训练学什么（待验证）

对预定历史训练查询，逐组运行真实三入口搜索，记录Recall@10和图搜索距离计算量。令 `R(q,S,L)` 为真实Recall、`D_G(q,S,L)` 为图搜索距离计算量，训练目标为：

`u(q,S,L) = R(q,S,L) − R(q,F3,L) − 0.05·[D_G(q,S,L)−D_G(q,F3,L)]/max(D_G(q,F3,L),1)`。

模型用 `φ(q,S,L)−φ(q,F3,L)` 预测上述差值，Fast3输入差严格为零。GT、真实搜索结果和Fast计算量只用于离线标签/评测，在线API不接收这些信息。0.05是固定的图工作量惩罚，不是实际延迟模型；最终仍须测端到端wall。

核心待检验差别是**整组三入口真实共同搜索的效用**：单入口各自找到的正确结果相加或取并集，不能代替共享候选池下的联合搜索结果。联合收益可能为正、零或负；不能预设单调性或子模性。

## 为什么优先这一项，以及可能怎样失败

| 调研方向 | 当前判断 |
| --- | --- |
| A：按搜索效用重选同预算候选池 | 尚缺优先重建池的证据，离线逐候选标签和重建画像/索引成本较高；先作有限池诊断 |
| B：预测单入口效用再独立排序 | 本地已有多项失败边界，不能把换损失、增加样本或更换模型名称当作机制进展；保留为同协议对照 |
| **C：固定主入口的真实三入口联合选择** | 保留池、表示和单view短名单，直接检验单入口监督遗漏的组合交互；作为唯一优先证伪方案 |

旧WebVid 1K/815候选的免费single oracle只支持历史池存在选择空间，不能证明新20K条件下的组合可预测或有完整成本收益。原论文、作者代码、本地适配和失败证据分列于[调研报告](entry_selection_research/20260908_v2/report.md)及[相关工作](entry_selection_research/20260908_v2/related_work.md)。GATE/旧NETG等已经覆盖学习入口、真实搜索监督、小导航层等要素，不能把这些本身当创新；当前也没有原创性证明。

最大的风险是现有向量特征看不到query特定的路径竞争，最优组合有收益也可能学不出来；其次是C8遗漏好入口、固定主入口限制过强，或额外路由成本吃掉收益。如果可加模型已达到同样效果，就不能归因于组合交互。失败后结束这个有限版本，不靠加view、在线probe、扩大网络或改搜索队列补救。

## 最小验证顺序与成本

以下是已设计、未执行的顺序；完整动作、验收和统计以[v2 minimum_gate.md](entry_selection_research/20260908_v2/minimum_gate.md)为准。各阶段结论只适用于预定有限家族，通过pilot不代表算法或论文贡献已经成立。

| 阶段 | 要回答的问题 | 通过条件摘要 |
| --- | --- | --- |
| G0 输入与实现验收 | 输入身份、C8/Fast3/anchor、实际三入口消费及count/plain是否一致，纯计时是否合格 | 契约与正确性检查通过；不据此判断性能 |
| G1 选择空间 | 池/短名单/排序分别损失多少；真实21组最优组合是否胜过Fast3、single排序和独立命中并集代理的真实重放 | 双数据集×两L四项主余量均≥0.5pp且校正区间下端>0；单列入口数与anchor限制，空间主要来自其他动作家族不支持当前方案 |
| G2 可预测性 | 固定小模型能否恢复联合收益，并胜过独立single模型及真实triple标签的无pair模型 | 预定12项Recall比较均≥0.3pp且校正区间下端>0；不通过不扩模型或扫参 |
| G3 完整成本 | 加上选入口开销后，是否仍胜过Fast3与独立single模型 | 按细则建立固定96项同时区间再作最多3%差异QPS匹配；四项主点对Fast3≥0.5pp、对匹配single模型≥0.3pp且区间下端>0；其余匹配稳定性、否决规则照细则执行 |

拟议输入固定WebVid/Yandex、CPU/raw-IP、原NSG/base/GT、独立QGT5K，paired Fast只用router_train后20K；前10K为已有历史使用的pilot，不能称新鲜测试集。仅从后20K预定抽2048条生成拟合标签；互斥D1/D2各512条，D1内嵌pool128/anchor64诊断。原始validation/held-out不进入该最小gate，既往访问和使用历史如实披露。

离线完整成本为 `exactGT + QGT + prototype + router-index + action-labels + pair-table + fit`，公共图构建另列；复用且历史耗时未知的项记null与原因。在线计入归一化、短名单检索、16个显式特征点积、pair表读取、21组40维打分、重置/去重、图搜索及结果写入；GT评分/hash/trace/JSON在timer外，count与plain独立。两张pair表在H=821时约5.39MB，操作量估算不替代实测wall。

本最小gate固定搜索调用总上限300万、4小时、8GiB新产物、80GiB RSS、16线程、单重进程，/data保留至少10GiB。G3固定16点/数据集，每点独立count一次、纯wall五轮；不因无匹配追加L或放宽容差。G3尚不包含无pair的triple标签模型wall，正式阶段须补齐，不能宣称已胜过全部可加方法。

最终标准保留双数据集至少两个相邻工作点同Recall QPS ≥+10%或同QPS Recall@10 ≥+1pp且校正区间支持，完整强基线、三独立构建、消融、尾部、离线成本，以及方法冻结后的held-out 10K×3。最小gate不降低这些要求。
