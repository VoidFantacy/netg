# ACSG 协作约定

在修改本项目之前，先阅读 `summary.md`，再完整阅读 `spec.md`：

- `summary.md` 是研究目标、实验路线、方法判断、数据集/资源优先级和 go/no-go 标准的权威说明。
- `spec.md` 是当前实现、真实调用链、数据与 metric 契约、artifact 格式和重跑依赖的权威说明。
- 实现事实冲突时，以当前源码、配置和实测结果为准，并先报告文档差异；不要用旧文档或旧结果覆盖当前工作区。

任何会改变实验定义、实现、输入、输出或结论的修改，都必须在同一任务中同步更新 `spec.md` 和 `summary.md`。包括但不限于：

- 数据集、query split、GT、metric、预处理或归一化；
- 底图/候选图后端、参数、ACO、hub、label、Router 或在线搜索策略；
- artifact/manifest/结果格式、评测指标、baseline、公平性口径、统计规则；
- 实验结果、结果解释、执行顺序、资源约束或 go/no-go 决策。

更新时保持职责分离：实现事实与重跑联动写入 `spec.md`；研究动机、实验设计、结果解释和优先级写入 `summary.md`。即使某次修改主要属于其中一份，也要检查另一份并补充其受影响内容；若确认无正文变化，至少核对其现有陈述没有因本次修改而失效。

不得擅自清理或覆盖用户的未提交文件、旧 artifact、日志和历史结果。共享底图必须冻结并可识别；base、预处理、metric、图、query split 或 GT 出现不兼容变化时，按 `spec.md` 的依赖表重跑全部受影响下游阶段。
