## 收益怎样表述

COCO/WebVid在两种K上有较清楚的收益区间；Flickr局部有效、幅度或曲线因预算变化，Yandex收益较弱且不稳定。这里不把“有限网格未覆盖”写成全局最佳，也不把不同L连线当成精确等Recall测量。16K表是造表用16,000条监督查询，每行最多32个ID，三个路由行去重前最多96个线上候选。

第4–5页使用E199最新四多模态曲线，补点版本是与原B32返回等价的工程优化实现。第6–8页使用E183完整窗口：COCO/WebVid/Yandex各10,000条，Flickr5,000条；其完整B32直接评分合并版本按原身份保留。两套数据分别标注，不混拼绝对QPS，不当作新盲确认。

本版只简化主图，来源仍为原固定A/B两批各512条的曝光查询；逐批原始结果保留在[E199 points.csv](../../entry_method_exploration/20261104_gate_timing_cost_v1/analysis/points.csv)。这不是新采样或重测，208个合并曲线点与前版逐字一致。旧版PDF和所有原图另保留原件。

低召回定义严格为单query的Recall@100<10%（GT100交集0–9个，恰好10个排除）。L200低召回数为COCO 0→1→1、Flickr0→0→0、WebVid142→53→46、Yandex174→86→85。GT10在WebVid救出113且新增24条，在Yandex救出128且新增40条；B32再救7/1条。WebVid的7条分为5条原NSG遗留与2条GT10新增。不同阶段救出率分母不同，顺序记账不声称独立因果贡献。

平均召回增益与跨10%门槛修复分开：COCO的B32在K100/L200提高1.3715个百分点，却未修复唯一低召回query；WebVid补回20,257个GT成员，仅75个来自原低召回队列，占0.37%。同L质量增加支付完整候选评分/合并费用，是否值得采用仍要对照附近GT10预算。

## COCO为什么看起来失败更多

分母为完整10,000条查询，0.01%就是1条。严格失败仍指Recall@100<10%。

| 搜索预算L | 原NSG失败数 | GT10失败数 | GT10+B32失败数 |
| --- | ---: | ---: | ---: |
| 100、128 | 1 | 2 | 2 |
| 200、400 | 0 | 1 | 1 |
| 800、1000、1200 | 0 | 0 | 0 |

GT10新增的是同一条原查询，零基行号4815。在L200/L400，NSG命中97/100，GT10和GT10+B32都命中3/100；L100/L128的NSG分别命中94/95，后两者仍为3。另一条原NSG低召回查询（零基行5741）仅在L100/L128中出现，三者都为9/100。因此新增严重失败来自NSG→GT10，B32在这些预算既没有再制造失败，也未修复既有失败；L≥800的已测点均无此类失败。

GT10改变主搜索入口，在有限预算下会得到不同返回；这解释了平均Recall提高为何不保证逐查询改善，但本轮未追踪该query的完整路径，不能进一步断言其具体几何成因。B32增加COCO平均召回与该严重失败仍未修复可以同时成立。[原GT/实际返回复核](reviews/coco_raw_audit.json)、[全L条数](analysis/COCO_low_counts_all_L.csv)、[低召回逐query命中数](analysis/COCO_low_query_hits.csv)均保留。

## 简短局限

1. **方法组合与工程实现成分较重。** 保留方案依托既有图搜索、画像路由、覆盖选表与精确合并；当前材料对独立算法机制、适用条件和创新性的论证仍不充分。这是当前研究定位判断，不是本轮文献新颖性检索结论。
2. **残差收益不全面。** 收益随数据、K/L及候选支持变化；COCO/WebVid的正面区间不能推广到Flickr/Yandex全部预算。平均召回改善也不等于严重低召回修复，GT10还可能新增低召回查询。固定图/表、已曝光窗口和有限预算限制结论范围。

这两点不撤销历史M5/B32/SQ的条件有效结果，也没有把已停止的双塔/门控路线恢复为当前方法。本轮仅整理已有数据，没有新增实验、GT、训练、计时或默认替换。
