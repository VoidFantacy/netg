# GT10 方法改进实验复盘：轻量 NETG、MLP 与强化学习

整理日期：2026-09-17。根据实验索引、详细记录以及关键原始报告、结果表整理。

这段时间的工作，主要是在回答一个问题：**能否保留轻量 NETG／Fast 的低在线成本，再利用 GT10、真实搜索监督或强化学习，选出更有效的三个入口？**

得到的结果是：GT10 画像值得保留；MLP、强化学习和后续画像改造都出现过局部正值，但尚未形成稳定优于原 GT10 的完整性能证据。后续增强没有成功，不等于 GT10 原有收益消失。方法默认仍为 WebVid 的 GT10-soft-t1、Yandex 的 GT10-hard。

本文重点复盘 9 月 9—14 日的方法实验，并补充此前轻量 NETG 与多视图整合的背景。Fast 在 8 月底已经形成，不能算成这几天新做出的算法。按本次要求，正文不展开 NSG 底层实现优化。

**阅读口径：**下面历史实验主要在 WebVid、Yandex 上进行，指标为当时的 **Recall@10**；`pp` 表示百分点，`L` 表示搜索预算。GT10 方法名中的“10”是训练目标数，与评测的 K 独立。9 月 15 日起的新实验已经改用 Recall@1、Recall@100，本文只复盘历史，不新增 Recall@10 测试。不同批次的绝对 QPS 不横向拼接；fit 用于拟合，monitor/cal 用于监控或选型，audit/validation 保留各自历史角色。多份开发数据已有重复使用，不能统一称为全新盲测。

## 1. 从原 NETG 整合到轻量 Fast，再到 GT10

### 1.1 轻量化究竟保留了什么

原 NETG 的主要链条是：用 ACO 与聚类选真实 hub，生成 query×hub 的搜索效用标签，训练 NeuralRouter 的入口表示，再用小索引完成路由。它并非完全没有真实搜索监督，但离线流程较重，而且单入口监督与最终三个入口联合搜索之间存在差距。

轻量 Fast 将入口选择和入口表示构造简化成以下流程：

1. 用一批 5K 查询做球面聚类，通过代表查询的精确 GT100 选出不重复的真实 base 节点作为 hub，即 QGT-Cover。
2. 使用另一批查询构造画像：根据查询的 GT1 目标与真实 hub 的关系，把查询方向累加到相应 hub。
3. 每个 hub 保存一条归一化画像向量，并与真实 base ID 绑定。
4. 在这些画像上构建 Micro-HNSW；在线只做一次小图检索，得到三个真实入口，再搜索原底图。

这里的画像，可以理解为“哪些查询适合从这个真实节点出发”的方向摘要。小 HNSW 索引的是画像，交给底图的仍是真实节点 ID。**Fast 的实际流程没有在线 MLP，也没有画像优化器训练；部分旧槽位仍叫 `NETG_AsymHNSW`，不能据名字认定内部仍在运行旧神经网络。**

这次整合的价值是减少复杂标注和优化环节，同时保留“真实 hub＋查询画像＋轻量路由”的整体结构。它仍依赖精确训练 GT，不能把已有 GT 后的秒级画像构建时间当成完整从零成本。

原始背景见 [Fast 与旧 NETG 复盘](experiment_history/01_fast_and_legacy.md)。

### 1.2 此前还试过哪些轻量整合

GT10 形成之前，已经尝试过多视图和效用监督。它们解释了为什么后来转向“把改进尽量放在线下，并保留一次小图路由”。

| 尝试 | 具体做法 | 实际结果与留下的问题 |
|---|---|---|
| 三视图 Fast 集成 | 三个聚类 seed 各建一套画像，每套取 top-8，合并后选三个真实入口 | 同 L 有小幅召回改善；但三路路由挤占搜索预算。改成三套 Micro-HNSW 后，在相近总距离计算量下，四个对照点仍均低于单 Fast；停止该版本。没有把未执行的完整 wall 当成实测失败。 |
| confidence-attention | 用每个视图 top1−top2 分差修正候选分数，选择共享系数 α | WebVid 通过的非零系数为 −0.5，Yandex 为 +0.5，共享交集为空。这是固定置信度公式的检验，没有训练 attention 网络或 MAML。 |
| 轻量效用排序器 | 在 Fast top-32 内，用真实单入口 Recall/NDC 标签学习加权内积与偏置 | WebVid 有小正值，Yandex 成本和质量不稳定；没有完整端到端优势。候选中存在好入口，模型却未可靠选出。 |
| 搜索获胜入口聚合／效用残差 | 用真实搜索标签重新聚合查询，或给原画像加带正负权重的查询残差 | WebVid 的残差版本在 validation10K 上有约 +0.077～+0.114 pp 的小收益，缺少跨数据与完整 QPS 证据；应保留这个局部信号。 |

这些尝试见 [多视图与置信度复盘](experiment_history/02_multiview_and_attention.md)、[搜索效用与表示改造](experiment_history/04_utility_and_representation.md)。它们是 GT10 的前置探索，不应倒写成全部建立在 GT10 之上的改进。

### 1.3 GT10 本身改了哪一步

GT10 保留 Fast 的真实 hub 与在线结构，把画像监督从一个 GT 目标扩展为十个 GT 目标。WebVid/Yandex 的真实 hub 数仍为 815/821，在线仍取三个入口。

对查询 q 的十个真实近邻，每个目标先向 hub 分配权重，再将十份权重平均：

- **hard：**每个目标只分给与其余弦相似度最高的真实 hub。
- **soft：**每个目标按温度 softmax 向全部 hub 分配权重。

记平均权重为 a(q,h)，则一条画像的构造可写成：

```text
P_h = normalize(normalize(raw_hub_h) + Σ_q a(q,h) · normalize(q))
```

每个查询的总权重仍为 1。GT10 没有把训练查询变成十倍，没有增加真实入口数量，也没有让查询时读取 GT。

E24 的同批 Fast20K／GT1-hard 对照中，WebVid 按 cal 预选 soft，Yandex 预选 hard；两者各有 3/5 个预算点同时提高 Recall@10 与单次实测 QPS。例如 WebVid L64 为 +0.525 pp／+3.51%，Yandex L128 为 +0.335 pp／+2.56%。同时，WebVid L128 的 Recall 下降 0.070 pp。一个构建、历史 validation2K、单次计时支持局部正信号，尚不足以说明整条曲线稳定占优。

后续 E27 发现，GT10-hard 的画像有效样本量中位数由 WebVid 的 16 增至 67.36、Yandex 的 22 增至 60.08；打乱目标尾部关联后，大多数对照反而变差。这支持“更充分地利用查询与多个目标的关系”的解释，但尚未独立拆分支持量、平滑作用和目标信息各自贡献。**它也不是简单地把 Micro-HNSW 搜得更精确：两个局部正点在精确画像选点下仍保留收益。**

证据：[E24 原报告](entry_method_exploration/20260910_gt_topk_profiles_v1/report.md)、[E27 机制复盘](experiment_history/16_gt10_mechanism.md)。

## 2. 监督学习路线：从轻量变换到 MLP，具体改过什么

### 2.1 A+B：一起学习画像和真实入口映射（E22）

这一版发生在 GT10 之前，目的是给轻量 Fast 加回可学习能力。它用 rank-8 残差改变画像，同时学习“画像槽位→真实 hub”的多对一映射；在线仍由小 HNSW 找槽位，再映射到真实入口。

双数据集、三 seed、两档标签 L 共训练 12 个模型；标注真实调用约 1.70 亿次，标注阶段约 6,640 秒，训练阶段约 1,041 秒。最后采用用户缩减后的单线程、每集 2K 查询、五 L 探索矩阵。

结果是训练集明显提高，cal 没有跟上：WebVid fit Recall 从 75.1765% 升到 78.2585%，cal 从 74.9805% 降到 74.6484%；Yandex 也出现同方向落差。最终十个点的 QPS 全部低于历史 Fast，小 L 质量也下降。学到的连续残差很小，主要变化来自映射，说明这次映射收益没有泛化；不能据此认定所有低秩模型都不行。

### 2.2 用真实三入口联合收益训练排序（E23）

针对单入口标签与实际三入口联合搜索不一致，下一版固定真实 ID 映射，直接生成真实三入口标签，训练完整矩阵或 rank-8 变换，并用 Fast 画像作锚定约束。

这一步已经使用联合搜索反馈，后来不能将它误写为“仍然只有单入口伪标签”。Yandex 的 rank-8 在五个 L 都有小幅 Recall 正值，但大部分点略慢，未形成清楚的整体优势。还有一个关键现象：同一入口的相对好坏，会随另外两个入口改变；把这种条件关系压成独立入口排序并不容易。

证据：[E22](experiment_history/11_ab_fixed_slot_exploration.md)、[E23](experiment_history/12_three_entry_rank_exploration.md)。

### 2.3 在 GT10 上训练共享 linear／MLP／自由残差（E28）

GT10 形成后，主要监督学习实验固定它的真实 hub，训练新的画像：

```text
GT10-hard 画像 P → 共享变换或自由残差 → 新画像 W → 重建 Micro-HNSW
```

三种表示为共享线性变换、小 MLP（d→64→d，ReLU），以及每个 hub 独立的自由残差。输出均归一化，并约束不要过度偏离 GT10。

具体训练流程是：

1. 每条 fit 查询收集 GT1-hard 与 GT10-hard 实际返回的三入口，并补齐到 8 个候选。
2. 枚举 8 选 3 的 56 个组合，逐个运行真实搜索，记录命中数和距离计算量。
3. 先按命中最多、再按 NDC 最少选择一个完整三入口教师。
4. 训练共享表示，使新画像评分偏好教师集合，同时保留 GT10 锚定约束。
5. 用 cal 选择冻结配置，导出画像并重建小图，再测完整查询流程。

这批有 224 万个逻辑三元组标签，其中约 197 万次为新真实搜索，另外复用兼容缓存；12 次、每次 80 epoch 的训练合计约 462 秒。**这里的 MLP 只离线运行，线上没有 query MLP 前向。**

代表性实测如下，均为 E28 同批 L128、历史 validation2K、三轮计时；共同训练锚点是 GT10-hard：

| 数据集 | 方法 | Recall@10 | QPS 中位数 |
|---|---|---:|---:|
| WebVid | GT10-hard | 74.175% | 2183.2 |
| WebVid | 共享 linear | 74.245% | 2177.6 |
| WebVid | 小 MLP | 74.205% | 2157.5 |
| Yandex | GT10-hard | 90.055% | 2123.4 |
| Yandex | 共享 linear | 89.945% | 2120.8 |
| Yandex | 小 MLP | 89.980% | 2119.4 |

MLP 并非所有点都差。WebVid L400 比 GT10-hard 多 0.240 pp，QPS 约持平；但低预算有退化，Yandex 没有统一改善，因此没有替换 WebVid 原 soft／Yandex 原 hard。

训练损失确实下降，可教师入口重合度没有随之上升。有限 C8 教师比原方法高 4.626/2.850 pp，只说明候选内有机会，不说明共享 MLP 已经学会，也不是可上线方法的收益。该轮预设性能门在 WebVid 的召回覆盖不足，不能单凭“门未通过”否定模型；上述判断同时依据实际覆盖区间和完整正负点。

原始证据：[E28 方法、训练与全部结果](entry_method_exploration/20260911_gt10_shared_transform_v1/report.md)。

### 2.4 怀疑教师、损失和优化器之后，都做了控制（E29—E32）

| 怀疑的问题 | 实际修改 | 结果 |
|---|---|---|
| 教师为了少算一点距离，要求本来已经正确的查询换入口 | E29 比较成本优先教师与“没有新增命中就保留原集合”的教师；同时比较集合交叉熵与 top-3 margin | 做了教师×损失的 2×2 对照，没有得到稳定双数据改善。 |
| 同样好的三入口不止一组，强迫模仿唯一答案不合理 | E30 同时接受命中与成本都严格并列的多个教师集合，并控制画像漂移 | 完整性能仍未稳定超过原 GT10。大量教师歧义存在，但这次修正没有解决主要问题。 |
| 是否只是没有训练充分 | E31 固定目标，改进优化并延长到 1,200 步 | WebVid 缓存候选内相对锚点约 +0.2115 pp，Yandex约 −0.0040 pp；损失变好没有自动转成检索改善。 |
| 模仿教师本身绕了弯路 | E32 对 56 个组合直接优化精确期望 Recall | fit 收益提高到 WebVid +1.1270 pp、Yandex +0.3010 pp；但 WebVid cal 相对默认仍微负，候选生成与评分成本也明显增加。 |

E32 是有限动作上的直接收益优化，不是多步构图 RL。它部署时需要两路候选和组合评分，已不再具有原来的一次轻量路由成本；因此不能只拿训练 Recall 宣称新方法成功。

这条路线实际排查了“单教师选择不当、损失不对齐、训练不充分”三类问题。证据支持它们会影响结果，但还不足以说明换一个更大 MLP 就能解决。详见 [E29](experiment_history/18_teacher_objective_alignment.md)、[E30](experiment_history/19_equivalent_teacher_sets.md)、[E31](experiment_history/20_training_effectiveness.md)、[E32](experiment_history/21_direct_reward_policy.md)。

## 3. 强化学习路线：不同版本的动作、训练和部署

这些实验不能统称为“给 GT10 加了一个 RL”。它们学习的对象不同，在线成本也不同。

### 3.1 直接学习小 HNSW 的删边策略（E33—E34）

E33 为小图底层的可删边学习 Bernoulli 保留概率，以真实搜索收益和总 NDC 为反馈，采用 REINFORCE。保留连通骨架，画像、真实 ID 和上层结构不变；训练后导出一张静态小图，在线不运行 RL。

两数据集约删除 30.56%/34.12% 的边，路由 NDC 降低约 18%～19%，但总 NDC 的变化不足 1%。WebVid 有局部质量正值，Yandex 开发结果为负；WebVid audit 的 RL 还没有胜过同出度随机删边对照。

E34 随后补齐五 L、五轮完整性能。WebVid 相对默认五点中四点 Recall 为负，Yandex 也只有一个点微正，QPS 改变很小。**少了小图边、少算了路由距离，没有转化成稳定的端到端优势。**

证据：[图边 RL](experiment_history/22_hnsw_edge_rl.md)、[完整性能补测](experiment_history/23_hnsw_rl_benchmark.md)。

### 3.2 查询时用小 MLP 换三个入口（E36）

E35 先确认当前小图强连通，并发现一些有用 hub 已被访问和评分，却没有最终选中。这促使 E36 直接学习组合选择：

1. 用当前 GT10 小 HNSW 一次取 8 个候选，从原 top-3 出发。
2. 每步允许换掉一个入口，或者停止，最多 3 步。
3. 用含 query 与画像交互特征的 MLP 为三入口集合打分；模型约 1,521 个参数。
4. 对所有 56 个集合保存真实联合搜索反馈，训练时复用缓存。
5. 比较 REINFORCE 与同一策略的精确动态规划梯度，避免把“用了 RL”本身当收益来源。

八次训练、合计 24,000 次更新已完成。该版的 MLP **需要在线运行**，与 E28 的离线 MLP 不同。

| E36 audit512，L128 | ΔRecall@10 | Δ完整 QPS | Δ总 NDC |
|---|---:|---:|---:|
| WebVid，所选 RL | −0.4688 pp | −9.32% | +0.388% |
| Yandex，所选 RL | +0.3906 pp | −8.30% | +0.283% |

Yandex 有局部质量收益，但支付了明显在线时间；WebVid 质量与速度均下降。当前实现即使早停，也先计算全部 56 个集合的特征和 MLP 分数。NDC 没有记录这部分特征与矩阵运算，所以“距离次数几乎没增加”不能说明总时间接近原方法。没有分段计时证据把全部差额精确归到某一个算子。

结果见 [E36 原报告](entry_method_exploration/20260911_query_swap_policy_v1/report.md)。这批没有证明 RL 优于同策略的精确优化，也没有部署为默认。

### 3.3 把学习移回离线：学画像，再重建小图（E37）

为保留原在线成本，E37 不再查询时换点，而是在 16 维查询统计基底内，用 256 个共享参数扰动整套画像。每次动作的实际反馈链为：

```text
采样画像参数 → 得到新画像 → 普通 HNSW 重建
            → 真实三入口搜索 → 命中、NDC、失败与漂移反馈
```

训练比较独立 Gaussian 采样的 RL 与成对扰动的 ES，使用相同目标及预算。两数据集、两 seed、两臂共 1,600 次更新、12,800 个候选图，训练约 1,536 秒；最后仅部署静态画像和小图。

结果没有形成稳定双数据收益，五 L 的完整 QPS 也没有明确改善。它属于参数策略搜索，尚不是根据构图状态进行长期规划的多步建图策略，不能把后者的能力写成已经实现。

证据：[E37](experiment_history/26_offline_profile_rl.md)。

### 3.4 从全局扰动改成单画像动作，再用完整反馈（E43—E49）

后续认为，一次动全部画像可能同时影响太多查询，于是 E43 固定其它画像，每次只改一个 hub 的画像，并比较局部 RL／ES。

最初每步看 128 条查询，反馈非常稀疏：每次 200 步训练里，WebVid 只有约 13～18 步、Yandex 只有约 3～7 步观察到质量变化。E44—E45 的全池对照确认，小批次确实会漏掉动作效果，但简单的原入口分层采样也没有稳定降低方差。

E46 因而实现完整三入口的精确反馈复用：同一查询、同一底图与搜索配置、同一完整三入口及约定顺序，可复用底图返回；小 HNSW 路由仍重新计算。这个改进降低了重复调用成本，允许 E47 对完整 4,096 条反馈查询训练，而不是只看小 batch。

E47 八次训练全部完成，约 5,910 万次小 HNSW 查询、228,832 次 NSG 调用，训练约 21 分钟。RL 在 monitor 上保留了小正值：WebVid 两 seed 为 +0.0781/+0.0098 pp，Yandex 为 0/+0.0781 pp。原统一继续门因 WebVid 的 ES 臂失败而停止预算扩展，**这个总门失败不能写成 RL 的这些局部正值不存在。**

E49 的完整五 L 测量仍未建立双数据前沿改善。WebVid 某些 L 有正值，高 L 又受损；Yandex 质量几乎不变。完整反馈解决了一部分“没看见效果”，尚未解决“学成更好的方法”。

证据：[E43](experiment_history/32_local_profile_rl.md)、[E46](experiment_history/35_exact_feedback_cache.md)、[E47 原模型表](entry_method_exploration/20260912_full_feedback_profile_rl_v1/results/models.csv)、[E49](experiment_history/38_frozen_local_rl_evaluation.md)。

### 3.5 找到好候选，却没有把它变成有效更新（E50—E53）

E50 检查完整训练轨迹后发现一个具体问题：在已经采到净正候选的 RL 步骤中，Adam 更新后的确定均值模型仍经常不改变训练池命中——WebVid 为 **184/214＝85.98%**，Yandex 为 **93/97＝95.88%**。

小图的入口选择具有离散边界。参数发生连续小变化，不一定改变最终三入口；采样候选跨过了边界，平均更新却可能仍留在原来区域。E51 的固定方向、不同半径控制支持存在这种转化缺口，也发现过大的步长会造成严重损伤。因此不能简单改成“把学习率加大”。

随后实际做了两个不同控制：

- **E52 直接择优提交：**每步真实评估 8 个 Gaussian 候选和原地不动，直接提交最好的合法候选。它是贪心搜索，**不是 RL**。
- **E53 RL 方向＋真实步长接受：**保留 RL／Adam 方向，真实评估四分之一步、半步、整步和不动，再决定接受哪个更新。

下面是各自两个 seed 的所选 monitor 增量，均为历史训练监控结果，不能当独立最终性能：

| 版本 | WebVid ΔRecall@10，两个 seed | Yandex ΔRecall@10，两个 seed |
|---|---:|---:|
| E47 完整反馈 RL | +0.0781 / +0.0098 pp | 0 / +0.0781 pp |
| E52 贪心候选提交 | +0.3125 / +0.2051 pp | +0.0586 / −0.0977 pp |
| E53 RL＋步长接受 | +0.1270 / +0.1562 pp | +0.0195 / +0.0293 pp |

这说明更新方式确实解释了一部分问题。WebVid 的直接择优比原 RL 有更明显的监控收益，Yandex 却出现 seed 间正负变化；RL 加真实接受也没有解决全部迁移问题。各算法后续轨迹会分岔，因此这里不是严格固定状态下的单因素比较，不能概括为“贪心永远比 RL 好”。

原数据：[E50 逐 run 统计](entry_method_exploration/20260912_candidate_commit_diagnosis_v1/results/runs.csv)、[E52 模型表](entry_method_exploration/20260912_direct_candidate_commit_v1/results/models.csv)、[E53 模型表](entry_method_exploration/20260912_feedback_step_rl_v1/results/models.csv)。

### 3.6 只学习构图空间，在线仍按原 GT10 评分（E54—E57）

前面的画像学习同时改变两个因素：画像评分，以及 HNSW 构建出的邻接关系。E48/E54 用四格控制分开检查，发现两者都可能影响结果，且 WebVid 与 Yandex 的表现不一致。

E56 因而只学习构图用向量 C：用 C 建图，再把图内查询评分向量逐字恢复为原 GT10 的 P。在线使用原 P 评分和新邻接，避免学习画像直接改变查询相似度。

四次训练在 monitor 上仍有小正值，但 cal 没有统一改善，最终没有被选为更好的方法。扩展到每集 19 个候选后，E57 选出的 WebVid 新候选来自 E52 贪心模型的拓扑版本，Yandex 来自 E53 RL 的画像＋拓扑版本；该选择与 E55 相同，因此沿用 E55 的整批测量，不能重复计成两套新性能实验。

这批每集 2K 查询、五 L、五轮完整计时，相对各自原 GT10 默认的 Recall@10 变化如下：

| 数据集／最终新候选 | L64 | L128 | L256 | L400 | L800 |
|---|---:|---:|---:|---:|---:|
| WebVid／贪心拓扑版，对原 soft | −0.120 pp | −0.045 pp | −0.065 pp | −0.025 pp | −0.005 pp |
| Yandex／RL 步长接受版，对原 hard | −0.075 pp | −0.075 pp | −0.050 pp | −0.050 pp | −0.050 pp |

十点 Recall 均略低，QPS 差异处于重复计时范围内，未形成替换原 GT10 的依据。这是这轮 RL／优化器研究比单个训练正值更有分量的结果。

证据：[E56](experiment_history/45_construction_only_rl.md)、[E57 选型与测量来源](experiment_history/46_expanded_final_comparison.md)、[最终配对 CSV](entry_method_exploration/20260912_expanded_final_comparison_v1/results/paired_comparisons.csv)。

## 4. 在 RL 之外继续改表示和画像，也实际试过

9 月 13 日的大部分后续尝试是确定性构造、真实效用筛选和静态修补，不宜全部归为强化学习。

### 4.1 保留旧收益、减少新损伤

早在 E25—E26，已经尝试根据查询在 GT1 与 GT10 之间选择，以及离线混合两套画像。双路门控有时略增 Recall，但多一次路由使 QPS 下降；单路收缩又经常削弱原 GT10 收益，未同时达到保留收益与减少损伤的目标。

E61—E65 又针对原方法遗漏的 GT 成员、零命中查询重新分配画像权重。它们有个别训练或开发正值，也会把原本正确的查询变成零命中，未获得稳定净收益。

详见 [E25 门控](experiment_history/14_selective_profile_gate.md)、[E26 收缩](experiment_history/15_profile_shrinkage.md)、[E61 遗漏目标](experiment_history/50_missing_target_profiles.md)、[E63 零命中重权](experiment_history/52_zero_hit_mass_v2.md)。

### 4.2 一个真实入口配多个画像

E66 给每个 hub 保留原画像，再增加两个查询方向的子画像。在线仍只使用一个小 HNSW，但取七个画像槽位、去重成三个真实入口。它与此前三套 Fast 集成不同：真实 hub 数不增加，增加的是同一 hub 的表示数量。

后续控制依次检查了重复画像、精确评分、小图搜索宽度、按真实 hub 计宽、保留层级和子画像收缩。E73 删除同 hub 字节完全相同的画像后，WebVid/Yandex 的槽位从 2445/2463 减到 1771/2067，得到 compact 版本。

Yandex 的 compact 在开发数据上有值得保留的局部信号：E74 历史开发 2048 条查询中，L128 比原 hard 高 0.2881 pp，QPS 中位数低 0.961%。它的描述性曲线插值有正值，但尚不是实测等 Recall 提速。WebVid 对原 soft 的 L128 下降 0.1123 pp，且新增零命中，不能称为跨数据改进。

E79—E82 进一步用 GT 目标方向、同 hub 条件目标、query＋目标联合分组来构造子画像。几何分组目标可以变好，真实搜索收益仍未稳定变好；精确画像排序对照也没有完全消除问题。

证据：[E66](experiment_history/55_multimode_index.md)、[E73](experiment_history/62_compact_modes.md)、[E74 完整开发性能](experiment_history/63_compact_wall.md)、[目标分组 E79](experiment_history/68_target_space_modes.md)、[联合分组 E81](experiment_history/70_joint_view_partition.md)。

### 4.3 补小图边、恢复父画像、组合修复

E83—E90 依次尝试同 hub 补边、依据查询排名缺口补边、真实单边效用筛选、按完整策略差异提议边，以及把受损子画像恢复成父画像。

有些动作在 fit 上有真实收益，合并后却非简单相加。以 E89 为例，筛选动作的单项净命中和为 WebVid 297、Yandex 125，实际合并后只有 224/114；迁移到辅助查询又进一步变化。E90 要求跨来源支持后，Yandex 没有动作通过，等于原 compact，不能将继承的 compact 收益计为新方法增量。

E92 将 WebVid 的补边与父画像恢复组合。它相对 compact 的修复后来确实迁移到了最终五个 L，但仍没有超过原 GT10-soft。这一批不少进展是在修复新多画像方案自己的退化，必须同时保留原 GT10 作为参照。

E93 先冻结候选选择，E94 再做每集 2K、五 L、五轮完整测量。L128 的代表结果为：

| E94 同批比较 | Recall@10 | QPS 中位数 |
|---|---:|---:|
| WebVid 原 GT10-soft | 74.190% | 1705.11 |
| WebVid compact 起点 | 73.535% | 1702.35 |
| WebVid 组合修复 | 73.805% | 1690.34 |
| Yandex 原 GT10-hard | 90.055% | 1710.92 |
| Yandex compact | 90.125% | 1705.89 |

WebVid 组合比 compact 多 0.270 pp，但比原 soft 少 0.385 pp；Yandex 低预算略有改善，高 L 出现损伤。完整矩阵仍没有稳定整体效率优势，默认保持。这里的历史 validation2000 并非全项目未见数据，本次遵守先冻结选择、最终结果不回流选型。

原始报告：[E94 最终比较](entry_method_exploration/20260913_until2100_v1/stage35_final_comparison_v1/report.md)；动作复盘：[E89](experiment_history/78_local_parent_restore.md)、[E90](experiment_history/79_cross_source_parent_restore.md)、[E92](experiment_history/81_composed_repair.md)。

### 4.4 最后试了闭式查询统计构图（E95）

9 月 14 日从原 GT10 出发，再试了一次实质不同于随机扰动的构造：根据训练查询的未中心化二阶矩，分别使用完整矩阵和对角尺度生成构图向量，用它们建小图，再恢复原 GT10 评分向量。

两数据集、两种构造、L64/L128 的八个全量开发点，Recall 全部下降，零命中全部净增。WebVid 的损伤较大，Yandex 也没有通过。路由 NDC 下降仍没有带来更好的搜索质量；按预定条件没有继续测新 QPS。

结合前面的更新控制、跨查询迁移和最终性能结果，E95 正式停止当前固定 hub 的画像／小图增强分支。它没有证明所有 RL 或入口学习都不可能，也没有否定原 GT10。

证据：[E95 复盘](experiment_history/87_query_moment_graph_and_branch_stop.md)、[原停止决定](entry_method_exploration/20260914_query_moment_graph_v1/decision.md)。

## 5. 这些尝试实际说明了什么

**第一，轻量化的方向保留下来了。**真实 hub、GT 引导的查询画像、一次小 HNSW 取三个入口，是这一系列方法的稳定骨架。GT10 在这个结构内增加目标关联信息，在线形式基本不变，是已保留的增量。

**第二，存在更好的三入口组合，不等于当前表示能选出来。**教师候选空间中的收益、精确画像排序、几何聚类目标和真实有限预算搜索效用，是不同层次。E23、E28—E32 逐步把监督靠近真实联合搜索，但共享画像仍难以表达部分查询相关的组合偏好。

**第三，RL 的问题不止是训练量。**E38—E47 确认过反馈稀疏和采样遗漏；E50—E53 又确认过“采到好候选，却更新不出效果”。补齐反馈、改变提交方式后有改善，跨查询、跨 seed 和跨 L 的迁移仍然不稳。因此不能把后续工作简单总结成“RL 还没训够”。

**第四，共享修改会同时影响获益和受损查询。**局部画像、父画像恢复、补边和组合实验中，确实出现过一部分查询变好、另一部分变差，以及动作合并后非加性的情况。这是已测动作的结果，不是所有共享表示都无解的证明。

**第五，在线增加复杂选择要有足够收益支付成本。**E36 是直接例子：总 NDC 增幅不到 1%，完整 QPS 却下降约 8%～9%。E28 的离线 MLP 没有这类在线前向成本，但仍会通过改变画像、入口与搜索路径影响时间，不能认为导出成静态向量后速度一定相同。

所以，本阶段得到的不是一个已经超越 GT10 的“RL＋MLP 最终版”，而是：**保留了原 GT10，并通过一系列实际控制缩小了继续研究的问题范围——新的表示或动作需要产生可迁移的三入口联合收益，优化器和训练预算本身不足以保证这一点。**
