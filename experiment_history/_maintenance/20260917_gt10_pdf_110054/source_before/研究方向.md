# GT10：OOD 入口选择方法与实验总结

整理日期：2026-09-17。本文合并当前方法说明与 GT10 形成后的实验复盘，供老师、师兄讨论。
研究定位：**面向查询与库向量分布不一致的 OOD 检索，在固定底层 NSG 上选择更有效的真实入口。**

**一、当前保留的方法（2026-09-10，E24）**

流程：QGT 选择真实入口 → GT10 构造查询画像 → Micro-HNSW 检索画像 → 从三个真实入口执行原 NSG 搜索。

| 配置 | WebVid | Yandex |
|---|---|---|
| 保留版本 | GT10-soft-t1 | GT10-hard |
| 真实入口数 | 815 | 821 |
| 画像训练查询数 | 20,000 | 20,000 |
| 每条查询使用的真实近邻 | GT 前 10 个 | GT 前 10 个 |
| GT 目标归属 | softmax，温度约 0.0162 | 归给最相近的入口 |
| 在线输出 | 3 个真实入口 | 3 个真实入口 |

1. **选择真实入口。**用独立 5K 查询做球面 k-means；每簇优先从代表查询的 exact GT100 中选一个未重复的真实库节点。聚类中心只辅助选点，最终入口是真实节点。
2. **计算查询归属。**对每条画像训练查询，比较其 10 个 GT 目标与各真实入口的余弦相似度；每个目标做 hard 或 soft 分配，再平均为查询到入口的权重 `a_ij`。hard 下，一条查询也可贡献给多个入口。
3. **聚合查询画像。**入口 j 的画像为 `p_j = unit(unit(x_hj) + Σ_i a_ij · unit(q_i))`。GT 目标决定权重，实际累加的是查询向量；真实入口提供权重为 1 的先验。画像有闭式解，当前 GT10 无需 MLP 或 RL 训练。
4. **在线选择入口。**在画像向量上构建 Micro-HNSW（M=16、efConstruction=200、efSearch=10）；检索三个画像，映射为绑定的真实入口 ID，再运行原 NSG。线上只查小图，不使用 GT 或重新计算归属。

OOD 针对性在于：用查询的真实目标建立“查询分布 → 库中入口”的联系，让路由画像描述哪些查询适合从该节点进入；最终搜索仍使用原数据集的内积指标。
画像训练使用独立于本次选型/审计片段的 20K 查询；hard/soft 与温度由历史开发搜索选择后冻结。这些数据存在其他历史实验使用，不能将整个流程称为全新盲测。
核心局限：**目标与入口的几何相近，是搜索效用的代理；画像公式没有直接优化三个入口的联合搜索收益。**
离线成本包含 exact GT、真实入口选择、画像聚合和小图构建；尚无完整重测的从零总耗时。

**二、当前效果（2026-09-17，五集 Recall@1/100 重测）**

NSG、GT10、GATE 采用相同搜索内核，正式计时同机单线程、包含入口路由。下表为达到 90% Recall 门槛时，既有默认相对 NSG 的 QPS 变化：

| 数据集及默认 | Recall@1 门槛下 | Recall@100 门槛下 |
|---|---:|---:|
| WebVid · soft | +24.99% | +0.79% |
| Yandex · hard | +9.63% | +6.96% |

这是达到门槛的最快实测预算比较，各点实际 Recall 不完全相同。完整曲线显示收益随预算变化；Deep/SIFT 有较小到中等收益，GIST 相对 NSG 没有稳定优势。
当前结果支持 GT10 有实际价值，尚不支持所有数据集、所有召回区间全面最优。以下改进实验未产生可稳定替换它的新默认。

**三、GT10 之后做过的改进（2026-09-10—09-14，E25—E95）**

本节数字为历史 Recall@10，pp 表示百分点；L 为搜索预算。后续新实验只测 Recall@1/100，GT10 名称中的 10 仍指训练目标数。

**09-10｜门控与画像混合（E25—E26）**

- 查询门控选择 GT1/GT10：少量召回改善被额外路由成本抵消。直接混合两种画像：多数点削弱原 GT10 收益。

**09-11｜机制分析、离线 MLP 与联合教师（E27—E32）**

- GT10-hard 的有效样本量中位数由 WebVid 16→67.36、Yandex 22→60.08；打乱 GT 关联后多数结果变差，支持多目标关联有作用，但信息与平滑作用尚未完全分离。
- 训练共享线性变换、小 MLP（d→64→d）和自由残差，离线导出画像、重建小 HNSW；线上无需运行网络。
- 每条查询取 8 个候选，枚举 56 个三入口组合，以真实搜索命中、距离次数产生教师。WebVid MLP 在 L400 相对 hard 提高 0.240 pp、QPS 约持平；低预算和 Yandex 未稳定改善。
- 继续试过无收益时保留原入口、多组等效教师、交叉熵/margin、延长训练和直接优化组合期望 Recall。训练改善未转化为稳定最终优势；直接组合评分还增加在线成本。

**09-11｜小路由图删边 RL、在线 MLP 换点（E33—E36）**

- RL 学习小 HNSW 边的保留概率，部署静态图：路由距离次数下降约 18%～19%，完整 QPS 未稳定改善。这些修改作用于入口路由小图。
- 在线 MLP 从 8 个候选中替换三入口或停止，最多三步，并做精确梯度对照。audit512、L128 上，WebVid Recall −0.4688 pp/QPS −9.32%，Yandex +0.3906 pp/−8.30%。
- 即使早停也先评分全部 56 个集合；距离计算次数未计入模型运算，因此距离次数少不保证速度快。

**09-12｜离线画像 RL、反馈与更新机制（E37—E59）**

- 离线扰动画像→重建小 HNSW→真实搜索奖励，比较 RL 与成对扰动 ES；从整套画像共享变换改为一次只动一个画像，仍未稳定改善。
- 小 batch 容易漏掉有效动作，改用完整训练池反馈与完整三入口的精确缓存。已有净正候选时，RL 更新后的均值模型仍不改变训练池命中的比例为 WebVid 85.98%、Yandex 95.88%。
- 非 RL 贪心提交的 WebVid 两 seed 在 monitor 上提高 0.3125/0.2051 pp，Yandex 一正一负；RL 方向配合真实步长接受，也只得到局部收益。
- 试过只学小图构建向量、建图后恢复原画像评分。每集扩展至 19 个候选并冻结选型后，最终两集×五预算的 Recall 均略低于原默认，QPS 差异在重复计时范围内。

**09-13｜目标重权、多画像和小图局部修复（E60—E94）**

- 固定 RL 动作在另一来源查询上做迁移支持检查，两集同时满足训练目标和辅助支持的状态均为 0/40。遗漏目标/失败查询重权有训练收益，也损伤原本正确的查询。
- 每个入口增加两个子画像，小图检索后去重成三入口；试过去重精简、搜索加宽、子画像收缩和目标分组。Yandex 精简版开发 L128 为 +0.2881 pp/QPS −0.96%，WebVid 未获同样改善。
- 再试小路由图补边、恢复父画像及组合修复。冻结最终比较中，WebVid 组合在 L128 比精简版高 0.270 pp，但比原 soft 低 0.385 pp；Yandex 精简版比 hard 高 0.070 pp，高预算又有损伤。

**09-14｜查询统计构图与分支停止（E95）**

- 用查询二阶矩的完整矩阵/对角尺度生成小图构建向量，建图后恢复原画像评分。两集×两种构造×两预算共八个开发点，Recall 全降、零命中全增，未继续测 QPS。
- 停止当前固定入口集合下的画像/小图增强分支。MLP、RL、表示改造均已实际验证；局部进展保留，尚无稳定最终替代方案。

**四、希望老师和师兄指导的问题**

1. 在固定底图、线上轻量的约束下，除了已有画像变换与候选换点，还可能有哪些实质不同的 OOD 入口选择机制？
2. 怎样把 OOD 查询—目标关联转化为更可迁移的三入口联合效用监督，避免只提高训练池命中？
3. 当前瓶颈更可能是固定真实入口集合、单画像表示，还是几何归属目标？哪一项值得优先做有区分力的小实验？
